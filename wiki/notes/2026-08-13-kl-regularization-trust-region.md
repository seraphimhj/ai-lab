# KL 正则不是“防止模型变坏”的装饰项：它其实在规定你允许优化走多远

> 命中薄弱点：**统一数学框架 + retrieval 以外·后训练 + 端到端闭环**。今天把 RLHF、PPO、DPO 里反复出现的 KL，从一个需要背诵的 penalty，重新看成“分布空间里的信任域”。

## 全局地图

### 一句话摘要

后训练不是无条件地把奖励推到最高，而是在“获得更多奖励”和“不要离开参考模型太远”之间做受约束优化；KL 系数决定的，本质上是模型能拿多少分布漂移去交换奖励。

### 结构地图

```text
参考模型 pi_ref
      |
      |  提供起点、语言先验与覆盖范围
      v
候选策略 pi_theta -- 产生回答 --> 奖励 r(x,y)
      |                              |
      |                              | 想继续增大
      +---------- KL 距离 -----------+
                     |
                     | 限制优化半径
                     v
        max [期望奖励 - beta * KL]
                     |
             解析解是指数倾斜
                     |
                     v
       pi*(y|x) proportional to
       pi_ref(y|x) * exp(r/beta)
                     |
          DPO 直接学习这层相对偏好
```

## 一、[骨] 为什么不能只最大化奖励？

设提示为 `x`，回答为 `y`，当前策略为 `pi_theta(y|x)`，奖励模型给出 `r(x,y)`。最直接的目标是：

```text
maximize_theta  E_{y ~ pi_theta(.|x)} [ r(x,y) ]
```

这句话看起来合理：奖励越高越好。但它藏着一个危险前提：**奖励函数在模型可能到达的所有区域都可靠。**

现实恰好相反。奖励模型只在有限的人类偏好数据上学过；一旦策略为追分而走到训练分布之外，奖励模型就可能把漏洞误认为能力。于是优化器并不是在问“什么回答真正更好”，而是在问：

> “哪里能让这个代理评分器给出最高分？”

这就是 reward hacking（奖励投机）的数学起点。它不是模型突然有了恶意，而是优化忠实执行了一个不完整目标。

因此我们加入参考模型 `pi_ref`：通常是 SFT 模型，代表优化开始前已经具备的语言分布。目标变成：

```text
maximize_theta
E_{y ~ pi_theta} [ r(x,y) ]
- beta * KL(pi_theta(.|x) || pi_ref(.|x))
```

这里的 `beta` 不是普通的“正则强度旋钮”。它是**奖励与分布位移之间的汇率**：模型多获得一单位奖励，最多值得付出多少“离开参考模型”的代价。

**结构标注：核心问题。** KL 的角色不是笼统地“让训练稳定”，而是限制策略进入奖励模型不可信的分布外区域。

### 碰撞问题

如果奖励模型完全正确、覆盖模型所有可能输出，你还需要 KL 吗？

答案应当是：从防止奖励投机的角度，不需要；只最大化真实奖励即可。KL 之所以必要，暴露的不是优化器不够强，而是**我们不信任自己的奖励函数**。

## 二、[骨] “KL 惩罚”其实是“信任域约束”的拉格朗日写法

更本真的问题不是“奖励减去 KL”，而是：

```text
maximize_theta  E[r(x,y)]
subject to      KL(pi_theta || pi_ref) <= epsilon
```

含义很直白：在距离参考模型不超过 `epsilon` 的范围里，找奖励最高的策略。

这是 trust region（信任域）：**我只在一个局部范围里相信当前代理目标的方向。** 走出这个范围后，奖励模型是否仍然可信，无法保证。

把约束写进拉格朗日函数，就得到：

```text
L(theta, beta)
= E[r(x,y)] - beta * (KL(pi_theta || pi_ref) - epsilon)
```

对固定的 `epsilon`，最后一项里的 `beta * epsilon` 与 `theta` 无关；忽略常数，就回到熟悉的：

```text
E[r] - beta * KL
```

所以两种常见说法其实是同一件事的两面：

```text
约束视角：我最多允许策略移动 epsilon
惩罚视角：每移动一单位 KL，要支付 beta
```

它们像预算与价格：

- `epsilon` 是你手里有多少“漂移预算”；
- `beta` 是每单位漂移的影子价格（shadow price）；
- 漂移预算越稀缺，影子价格通常越高。

这也是 PPO 中常见自适应 KL 控制的理由：如果实际 KL 超过目标，就提高 `beta`；如果远低于目标，就降低 `beta`。系统真正想守住的是**移动半径**，惩罚系数只是控制器。

**结构标注：核心推导。** 从约束优化到拉格朗日形式，解释了 KL penalty 与 trust region 并非两套技巧。

### 注疏：一条“侧光”

这里和数据库的查询优化、控制系统的模型预测控制有同一个形状：模型只在局部可信，于是每次沿代理模型建议的方向走一小步，重新观察，再更新下一步。所谓“稳定”，不是永远不动，而是**别一次走出认知边界**。

### 压力测试

有人反驳：“只要把 `beta` 调得很大，就能保证安全。”这个说法错在哪里？

错在它只限制“离参考模型多远”，不保证“往哪个方向走”。如果参考模型本身有缺陷，或奖励模型在参考模型附近就存在系统性盲区，大 `beta` 只能让缺陷变化得更慢，不能把错误方向变正确。

## 三、[肌] 一笔两答案的概率账：β 到底在控制什么？

假设同一提示只有两个候选回答：

```text
参考模型概率：
pi_ref(A) = 0.8
pi_ref(B) = 0.2

奖励：
r(A) = 0
r(B) = 2
```

最优策略不是简单地把全部概率压给 B，而是对参考分布做“指数倾斜”：

```text
pi*(y) proportional to pi_ref(y) * exp(r(y) / beta)
```

看两个回答的赔率比：

```text
pi*(B) / pi*(A)
= [pi_ref(B) / pi_ref(A)] * exp((r(B)-r(A))/beta)
= 0.25 * exp(2/beta)
```

- 当 `beta` 很大，`exp(2/beta)` 接近 1，策略接近参考模型；
- 当 `beta` 变小，奖励差被放大，B 会迅速夺走概率质量；
- 当 `beta -> 0`，策略趋向只选奖励最高的答案。

关键不是“B 的奖励是 2”，而是：**奖励差除以 β 后，能否推翻参考模型原有的概率赔率。**

这给了 `beta` 一个温度解释：

```text
高 beta：冷静，尊重先验，奖励只能轻推
低 beta：激进，奖励差被放大，策略容易集中
```

以上例子在支持第二节：KL 不是把参数拉回某个点，而是在控制整份输出概率质量如何重新分配。

**结构标注：数值直觉。** β 决定奖励差改写参考赔率的力度。

## 四、[骨] 指数倾斜：RLHF 与 DPO 共享的那层骨架

对每个提示 `x`，考虑在所有输出分布 `pi` 上优化：

```text
maximize_pi
sum_y pi(y|x) r(x,y)
- beta * sum_y pi(y|x) log[pi(y|x)/pi_ref(y|x)]
```

再加归一化约束：

```text
sum_y pi(y|x) = 1
```

对 `pi(y|x)` 求驻点，可得到：

```text
pi*(y|x)
= pi_ref(y|x) * exp(r(x,y)/beta) / Z(x)
```

其中 `Z(x)` 只是让概率加起来等于 1 的归一化常数。

把式子反过来写：

```text
r(x,y)
= beta * log[pi*(y|x)/pi_ref(y|x)] + beta * log Z(x)
```

现在比较同一提示下的优选回答 `y_w` 和落选回答 `y_l`。因为 `log Z(x)` 相同，相减后消失：

```text
r(x,y_w) - r(x,y_l)
= beta * {
    log[pi*(y_w|x)/pi_ref(y_w|x)]
  - log[pi*(y_l|x)/pi_ref(y_l|x)]
  }
```

这正是 DPO 的入口。DPO 不再显式训练奖励模型、再用 PPO 优化策略；它直接要求偏好数据中的胜者，相对于参考模型获得更大的 log-probability 提升：

```text
DPO 学的不是：pi_theta(y_w) 必须绝对很大
而是：相对 pi_ref，胜者应比败者得到更多概率增量
```

所以 RLHF 与 DPO 的共同骨架是：

```text
人类偏好
   |
   +--> RLHF: 先拟合 reward，再做 KL 约束策略优化
   |
   +--> DPO: 消去显式 reward，直接拟合最优策略的赔率关系
```

DPO 省掉的是训练管线中的一个显式阶段，不是删掉了“奖励”或“KL”的思想。参考模型仍在每个概率比里；`beta` 仍规定偏好证据能把策略推离参考分布多远。

**结构标注：全文主轴。** 指数倾斜是“RLHF 的受约束优化”与“DPO 的相对赔率学习”之间的桥。

### 你可以停十秒想一下

DPO 为什么必须比较 `pi_theta / pi_ref`，而不只比较 `pi_theta(y_w)` 与 `pi_theta(y_l)`？

因为偏好训练想学的是**相对于原有模型，该把概率质量往哪里搬**。没有参考模型，就失去了“移动量”的坐标系，也失去了对分布漂移的显式约束。

## 五、[肌] 三个容易被“KL 正则”四个字掩盖的细节

### 1. KL 有方向，不是普通距离

常见目标使用：

```text
KL(pi_theta || pi_ref)
= E_{y ~ pi_theta} [log pi_theta(y) - log pi_ref(y)]
```

它主要在当前策略实际会生成的区域计算代价。如果策略把某些参考模型会生成的模式彻底丢掉，由于这些模式很少从 `pi_theta` 采到，惩罚未必像对称距离那样强烈。

因此 KL 不是几何意义上对称的“相隔多远”。交换顺序会改变优化行为。这里使用 forward/reverse KL 的命名在不同文献中偶有混乱，最稳妥的办法是直接看期望到底从哪个分布采样。

### 2. 序列 KL 是逐 token 对数比的累积

对自回归模型：

```text
log pi(y|x)
= sum_t log pi(y_t | x, y_<t)
```

所以单条序列的 KL 代理通常表现为：

```text
sum_t [
  log pi_theta(y_t | x,y_<t)
  - log pi_ref(y_t | x,y_<t)
]
```

这意味着长度会进入账本：序列越长，可累积的偏离项越多。实现里若对 token 求和还是求平均、奖励是序列级还是 token 级、EOS 如何处理，都会改变实际优化目标。

### 3. “平均 KL 合理”不代表每个子群都安全

若只约束整个 batch 的平均 KL：

```text
mean_x KL_x <= epsilon
```

模型可能在大量普通样本上几乎不动，却在少量高风险提示上发生巨大漂移，平均后仍然达标。

这和此前讨论的“平均抹掉决定性少数信号”完全同构：

```text
平均 benchmark 掩盖失败子集
平均 KL        掩盖高漂移子集
```

更可靠的监控应同时看：KL 分位数、按任务切片的 KL、长度条件下的 KL，以及奖励提升与 KL 消耗的联合曲线。

以上三点在支持主轴：一句“加 KL 保稳定”远远不够；方向、粒度和聚合方式决定它实际约束了什么。

**结构标注：实现边界。** 把抽象目标落到序列模型和评测切片，揭示平均数背后的盲区。

## 六、[骨] KL 能筑围栏，但不能校准指南针

把今天的目标放回端到端闭环：

```text
偏好数据
   |
   v
奖励模型/隐式偏好目标
   |
   v
策略优化 -- 受 KL 限制 --> 新策略
   |                         |
   |                         v
   +------ 生成新数据 <--- 线上用户
```

KL 只处理其中一个问题：**策略更新不要一步进入奖励模型陌生的区域。**

它处理不了：

1. 偏好数据本身是否代表线上用户；
2. 标注者是否偏爱冗长、迎合或特定文风；
3. 奖励模型是否遗漏真实性、安全性等关键维度；
4. 参考模型是否已经带有系统性偏差；
5. 平均 KL 是否掩盖特定任务上的极端漂移。

因此，一个更准确的工程判断不是：

> “我们加了 KL，所以模型不会 reward hack。”

而是：

> “KL 把策略暂时限制在奖励模型相对可信的邻域；这个邻域有多可信，仍需独立评测。”

这也解释了为什么训练中经常出现 reward 上升、KL 可控，但真实质量下降：围栏没有倒，**指南针本身偏了**。

**结构标注：结论与边界。** KL 是分布漂移控制器，不是真实目标的替代品。

## 一页纸复盘

### 统一框架

```text
原问题：
maximize E[r]
subject to KL(pi || pi_ref) <= epsilon

拉格朗日形式：
maximize E[r] - beta * KL(pi || pi_ref)

最优分布：
pi*(y|x) proportional to pi_ref(y|x) * exp(r(x,y)/beta)

DPO 的桥：
r(x,y) = beta * log(pi*(y|x)/pi_ref(y|x)) + prompt常数
```

### 四句带走

1. `pi_ref` 提供的不是标准答案，而是策略移动的坐标原点。
2. `beta` 是奖励与分布漂移之间的汇率；小 β 激进，大 β 保守。
3. DPO 没有抛弃 RLHF 的 KL 骨架，而是消去了显式奖励模型这层中间变量。
4. KL 只能限制离开旧分布的速度，不能证明奖励方向正确。
