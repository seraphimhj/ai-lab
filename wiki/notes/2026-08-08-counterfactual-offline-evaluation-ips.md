# 伴读：离线高分为什么可能让 Agent 上线变差？——反事实评估与 IPS

> 本次命中：**模型评估主线 + Agent / 工具使用主线 + 端到端闭环薄弱点**。今天补的是一个常被漏掉的环节：线上日志不是客观考卷，而是旧策略主动选择后留下的数据。

## 全局地图

### 一句话摘要

只用旧系统日志比较新旧策略，会把“旧策略选择看什么”误当成“世界本来是什么样”；反事实评估用倾向概率把这层选择偏差显式记账，但它能纠偏的前提是覆盖，代价是方差。

### 结构地图

```text
真实问题：新策略上线后会得到多少回报？
                |
                v
只能看到旧策略生成的日志
(context, action, reward, propensity)
                |
                +--> 直接回放：低方差，但只认识旧策略走过的路
                |
                +--> IPS：按概率比重加权，能纠偏，但可能高方差
                |
                +--> DM：训练回报模型，稳定，但会继承模型偏差
                |
                `--> DR：让 IPS 和回报模型互相兜底

不可绕过的边界：
没有覆盖 -> 没有证据 -> 再聪明的估计器也造不出反事实
```

### 段落分类（Agent 判断，可覆盖）

- [骨] 日志不是被动观测，而是旧策略筛选后的世界
- [骨] IPS 为什么能纠偏：把“常被旧策略选择的样本”降权
- [肌] 一个 Agent 工具选择的例子
- [骨] 支持集与方差：无偏不等于可用
- [肌] DM、SNIPS、DR 各自在修什么
- [骨] 端到端闭环：评估协议会反过来塑造策略

## 逐段伴读

## 1. [骨] 日志不是考卷，是旧策略留下的足迹

假设一个 Agent 面对用户问题 `x`，可以选择动作 `a`：直接回答、搜索网页、查内部知识库，或者调用代码工具。旧 Agent 的策略记作：

```text
mu(a | x)
```

它表示：在上下文 `x` 下，旧 Agent 选择动作 `a` 的概率。日志里保存了它真正选过的动作及结果：

```text
(x, a, r)
```

其中 `r` 是成功、用户满意度或任务得分。

危险的直觉是：拿新策略 `pi` 到这批日志上跑一遍，看看它建议的动作是否和高回报动作一致，就能判断它是否更好。

问题在于，我们只观察到了**旧策略实际选择的动作所产生的回报**。同一个上下文里，旧策略选择了“查知识库”并成功，我们并不知道“搜索网页”或“直接回答”会怎样。那两个结果不是零，而是根本没有发生。

这叫：

- **Bandit feedback（老虎机式反馈）**：每轮只看到被选动作的回报。
- **Counterfactual（反事实）**：同一时刻未被选择的动作本来会有什么结果。
- **Logging policy / behavior policy（日志策略 / 行为策略）**：生成这批数据的旧策略 `mu`。
- **Target policy（目标策略）**：我们想离线评估的新策略 `pi`。

**结构标注：核心问题。** 评测数据不是独立于模型存在的；策略参与了数据生成，因此“数据 -> 模型 -> 评测”其实已经闭成了环。

### 碰撞

先不要急着看公式：如果旧 Agent 几乎从不调用代码工具，而新 Agent 的主要改进恰恰是更会调用代码工具，那么旧日志能证明新 Agent 的改进吗？

答案不是“证明不了效果有多大”，而是更严格的：**在那部分行为上，日志几乎没有识别能力。**

## 2. [骨] IPS：不是给成功样本加权，而是给“稀有选择”加权

**Inverse Propensity Scoring（逆倾向评分，IPS）**的核心估计式是：

```text
V_IPS(pi)
= average over logged events of
  [ pi(a_i | x_i) / mu(a_i | x_i) ] * r_i
```

先逐项读，不要背公式。

- `mu(a_i | x_i)`：旧策略当时有多大概率选中日志里的动作。
- `pi(a_i | x_i)`：新策略在同一上下文会给这个动作多大概率。
- 两者之比 `pi / mu`：这条日志对新策略有多大代表性。

为什么要除以旧策略概率？

假设旧策略特别爱选“直接回答”。日志里自然会堆满直接回答的结果。样本多，不代表这个动作在真实世界更重要，只代表旧策略更爱走这条路。IPS 用 `1 / mu` 抵消旧策略造成的过度采样；某动作越少被旧策略选择，一旦被观察到，它就代表越大一片被旧策略忽略的可能世界。

反过来，如果新策略根本不会选择日志中的某动作，那么 `pi` 接近零，这条记录对新策略的价值估计就几乎没有贡献。

**意译成一句话：**

> IPS asks not only “what reward did this action get?” but also “how surprising was it that the old policy chose this action?”  
> IPS 不只问“这个动作拿了多少回报”，还问“旧策略选中它有多罕见”。

**结构标注：核心机制。** IPS 把数据生成机制写进评估公式，纠正“谁被看见得更多”造成的选择偏差。

### 注疏：它和训练中的 importance sampling 是同一副骨架

**Importance sampling（重要性采样）**本质上是在一个分布下采样，却估计另一个分布下的期望。这里：

```text
数据来自 mu
目标属于 pi
概率比 pi / mu 负责换分布
```

这和 off-policy reinforcement learning（离策略强化学习）里的概率比不是“有点像”，而是同一个换测度操作。不同领域换了名词，数学动作没换。

## 3. [肌] 放进工具型 Agent，会发生什么？

设旧 Agent 遇到计算题时：

- 大多数时候直接心算；
- 少数时候调用计算器；
- 极少时候调用 Python。

现在有个新 Agent 更愿意调用 Python，尤其在长计算链上。直接在旧日志里统计“Python 调用后的平均成功率”会遇到两个混杂：

1. **选择难度不同。** 旧 Agent 可能只在最难的问题上才调用 Python，因此 Python 样本天然更难。
2. **样本覆盖不足。** 新 Agent 想在中等难度题上调用 Python，但旧日志中这类 `(中等难度, Python)` 几乎不存在。

第一个问题是选择偏差，已知且可信的倾向概率可以帮助纠正。第二个问题更根本：如果旧策略在某类上下文从不选 Python，分母 `mu(Python | x)` 为零，IPS 也无能为力。

这就是 **positivity / overlap（正值性 / 覆盖）** 条件：

```text
只要 pi(a | x) > 0，就必须有 mu(a | x) > 0。
```

换成人话：新策略想走的每一条路，旧系统至少得探索过一点。

**结构标注：具体化论据。** Agent 的“工具选择评测”不是普通分类准确率；动作会改变后续观察，日志因此带有策略指纹。

以上 1 段在支持第二节的论证。

## 4. [骨] 最重要的裂缝：无偏，不等于可靠

IPS 常被介绍为“无偏估计”，这句话只说了一半。

当旧策略极少选择某动作时，`mu(a | x)` 很小，权重 `pi / mu` 就会很大。于是少数几条日志可以主宰整个估计。理论上，多次重复采样后的平均值可能对；现实中，你只有这一份有限日志，估计值会剧烈抖动。

```text
小 propensity
      |
      v
大 importance weight
      |
      v
少数样本支配总体
      |
      v
高方差、置信区间变宽、结果不稳定
```

所以反事实评估中存在一条核心交换：

```text
更强纠偏 <--------------------> 更低方差
```

常见的 **weight clipping（权重截断）** 会给极端权重设上限。它降低方差，却重新引入偏差。这里没有“正确参数”自动出现；截断阈值表达的是你愿意用多少偏差换多少稳定性。

这也解释了为什么只汇报一个 IPS 点估计远远不够。至少还应看：

- 最大权重和权重分布；
- **Effective Sample Size（有效样本量，ESS）**；
- 不同截断阈值下结论是否翻转；
- 置信区间，而非只有均值；
- 新旧策略的动作分布距离。

**结构标注：最强限定。** “无偏”是估计器在理想重复实验中的性质，不是当前这份数据足够可信的保证。

### 压力测试

如果两个新策略的 IPS 分数一个更高，但它的结果几乎由几条超大权重样本决定；另一个略低，却在广泛覆盖区间内稳定——你会部署哪个？

真正成熟的答案通常不是直接二选一，而是：**把前者识别为需要在线小流量探索的高不确定性候选，而不是离线冠军。**

## 5. [肌] 四种估计器，其实在分配“偏差预算”和“方差预算”

### 5.1 Direct Method（直接法，DM）

先训练一个回报模型：

```text
r_hat(x, a)
```

再用它预测新策略每个动作的回报。

优点：即使日志没刚好执行那个动作，模型也能泛化，通常方差低。缺点：如果回报模型在策略最关心的区域预测错了，评估会稳定地错。

### 5.2 IPS

少依赖回报模型，直接用真实观测回报纠偏。覆盖好时更可信；倾向概率小或记录错误时方差爆炸。

### 5.3 SNIPS

**Self-Normalized IPS（自归一化 IPS，SNIPS）**用所有重要性权重之和做归一化。它通常更稳定，但不再严格无偏。它主动做了一笔交易：少量偏差换有限样本下的可用性。

### 5.4 Doubly Robust（双重稳健，DR）

DR 先用回报模型给出基线预测，再用 IPS 对“真实回报与预测回报之间的残差”做纠偏：

```text
DR = 回报模型预测
   + importance weight * (真实回报 - 回报模型预测)
```

它的精髓不是“把两个分数平均”，而是让两种错误模式互补：

- 回报模型靠谱时，残差小，IPS 的高方差被压住；
- 回报模型有偏时，日志中的真实回报可校正它；
- 在适当条件下，行为策略模型或回报模型有一边估对，就仍可能得到一致估计。

但“双重稳健”不等于“双重保险，永不出错”。如果覆盖差、倾向概率记录错，同时回报模型又在新策略区域外推，DR 仍会失败。

**结构标注：方法谱系。** DM、IPS、SNIPS、DR 的差异不是四套孤立技巧，而是对模型偏差、采样方差和覆盖不足的不同分工。

以上 4 个方法在支持“评估是偏差-方差-覆盖三方权衡”的骨架段。

## 6. [骨] 端到端闭环：评估协议会反过来塑造策略

现在把链条接起来：

```text
旧策略 mu
  -> 决定采集哪些动作
  -> 形成带选择偏差的日志
  -> 离线估计器给新策略打分
  -> 团队选择“分最高”的策略
  -> 新策略成为下一轮日志策略
```

如果评估只奖励旧日志覆盖良好的行为，优化过程会偏爱“像旧策略、但在旧指标上更熟练”的候选；真正有新行为的策略因为缺少反事实证据，反而显得风险更大。长期看，评估协议会造成**行为保守化**。

反过来，如果为了覆盖而让日志策略持续做少量随机探索，就会牺牲一部分短期线上收益，却购买未来评估所需的信息。探索不是只为训练 RL；它也是在为未来的因果识别交“数据税”。

这里的论证结构，和主动学习（active learning）是同一个形状：

```text
今天选择采什么数据
        |
        v
决定明天哪些问题可以被可靠回答
```

**结构标注：闭环结论。** 评测不是流水线末端的裁判，而是决定下一轮数据分布的控制器。


### 读后一句话

请在心里完成这句，不必复述本文：

> “如果一个新 Agent 的优势主要发生在旧 Agent 从未尝试过的动作上，那么我会把离线高分或低分理解为 ________。”

一个达到 L2 的判断，不会只说“IPS 有偏差”，而会明确区分：**性能证据**和**覆盖证据**。

### 终局问题

如果线上探索既会伤害部分真实用户，又是未来可靠评估不可缺少的条件，那么：**谁有权决定为了减少未来的不确定性，让今天的哪些用户承担探索成本？**

这已经不只是估计器问题，而是实验治理问题。
