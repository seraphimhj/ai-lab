# 从 GAE 到 GRPO：不用 Critic，不等于没有基线

> 本次命中：*统一数学框架* + *端到端闭环* + *retrieval 以外·后训练*；递进昨天的 GAE：今天只追一件事——GRPO 拿掉 value model 之后，优势信号究竟从哪里来，又付出了什么代价。

## 全局地图

### 一句话摘要

GRPO 不是“无 critic 的 PPO 换皮”，而是把“跨时间估计回报”的问题改写成“同一道题内比较多个回答”的问题：它用组内相对奖励充当 baseline，省掉 value model，却把可靠性押在了采样组和奖励模型上。

### 结构地图

```text
REINFORCE: 回报直接乘梯度，方差很大
    |
    +-- 加 baseline，但不能依赖当前 action
            |
            +-- Actor-Critic / GAE
            |      用 value model 跨时间估计优势
            |
            +-- GRPO
                   同一 prompt 采样一组回答
                   用组内相对奖励估计优势
                           |
                           +-- 省掉 critic
                           +-- 引入组内采样与奖励偏差
```

## 逐段伴读

### 1. [骨] Baseline 不是奖励门槛，而是方差控制器

策略梯度最朴素的形状是：

```text
gradient estimate = score-function gradient * return
                  = grad log pi(action | state) * R
```

如果一次采样得了 1 分，另一次得了 0 分，我们当然可以直接拿 `R` 更新。但绝对分数经常混着两类东西：

1. 这个动作到底好不好；
2. 这道题本来就容易还是难。

于是我们减去一个 baseline：

```text
advantage estimate = R - b
```

只要 `b` 不偷看“当前实际采了哪个 action”，减去它通常不会改变策略梯度的期望，却能显著减少方差。它回答的不是“合格线是多少”，而是：

> 在这个处境下，本来可以期待多少？当前动作比这个期待好还是坏？

这正是 *control variate（控制变量）* 的思想：不改变我们想估计的平均方向，只消掉与目标无关的共同波动。

*结构标注：核心统一框架。GAE、critic、GRPO 的共同祖先不是 PPO，而是 policy gradient 中的 baseline。*

#### 注疏·逆光

最容易犯的错误是把 baseline 当作训练目标：“奖励低于均值，所以这个答案一定错。”并不是。baseline 只决定更新方向和相对强度；一个客观上不错的答案，只要比同组其他答案差，也可能获得负优势。

#### 碰撞

*The baseline is not a passing score; it is a variance-reduction device.*  
*基线不是及格线，而是降方差装置。*

先把这句话压在心里：如果某个 prompt 的整组回答全都很差，GRPO 仍会选出其中“相对最好”的一个并强化它。这里已经埋下了后面的风险。

### 2. [骨] GAE 和 GRPO，替换的是“本来可以期待多少”的估计器

昨天的 GAE 面对的是一条长轨迹：第 t 步动作之后，还有 t+1、t+2……的后果。它用 value model 估计 `V(s_t)`，再把多步 TD residual 按 lambda 衰减组合起来：

```text
delta_t = r_t + gamma * V(s_{t+1}) - V(s_t)
A_t     = delta_t + gamma*lambda*delta_{t+1} + ...
```

所以 GAE 的比较轴是：

```text
当前动作的实际后果  vs  critic 对当前状态的期待
```

GRPO 通常面对可整段评分的回答。对同一个 prompt `x`，从旧策略采样 G 个回答：

```text
y_1, y_2, ..., y_G
```

奖励模型或可验证规则给出：

```text
r_1, r_2, ..., r_G
```

然后用组内统计量构造优势，常见形状是：

```text
A_i = (r_i - mean(r_1...r_G)) / (std(r_1...r_G) + epsilon)
```

因此 GRPO 的比较轴变成：

```text
这个回答的得分  vs  同一道题上同一策略其他回答的平均表现
```

*结构标注：核心转换。GAE 用跨时间的 value 预测作参照；GRPO 用同题并行采样的经验分布作参照。*

#### 旁逸：它和 InfoNCE 是同一个形状吗？

很像，但不能画等号：两者都让样本在一个局部集合里竞争，绝对尺度退居其次；InfoNCE 通常比较表示相似度并优化分类式目标，GRPO 比较策略样本的奖励并优化策略梯度。它们共享“组内相对化”的形状，却不是同一个估计问题。

### 3. [肌] 一组回答如何变成 token 更新

一个回答只得到一个序列级优势 `A_i`，但更新发生在每个 token 上。简化后可以这样看：

```text
answer y_i gets one A_i

 token 1   token 2   token 3   ...   token T
    |         |         |                |
    +---------+---------+----------------+
                  share A_i
```

PPO/GRPO 风格的 surrogate objective 再用旧、新策略概率比限制更新：

```text
ratio_t = pi_new(token_t | prefix) / pi_old(token_t | prefix)
objective_t = min(ratio_t * A_i,
                  clipped(ratio_t) * A_i)
```

外加对 reference policy 的 KL 约束，防止策略整体漂得太远。

这揭示一个关键事实：GRPO 去掉了 critic，却没有自动解决 token-level credit assignment。整段回答得 1 分时，组成它的所有 token 往往共享同一个方向；究竟是哪一步推理带来了成功，仍没有被精确识别。

*结构标注：证据展开。序列级相对奖励经过 PPO 式概率比，广播到 token 级更新。以上 1 段支持“省掉 critic 不等于解决信用分配”。*

### 4. [骨] 不用 Critic，省的是模型；新增的是采样账和偏差账

GRPO 的收益很实在：

- 不必训练、存储、服务一个与 policy 同规模的 value model；
- 避免 critic 拟合不准后把系统性偏差写进优势；
- 同题比较会消掉一部分题目难度差异：难题整体低分、易题整体高分，不再直接主导梯度尺度。

但它并非免费午餐。

#### 代价一：组小，baseline 噪声大

组均值只是期望奖励的 Monte Carlo 估计。每个 prompt 只采很少几个答案时，一两个异常样本就会显著移动均值和标准差。critic 把信息跨许多状态共享；GRPO 则主要依赖当前 prompt 的这一小组样本。

#### 代价二：组内无差异，就几乎没有学习信号

如果所有回答奖励都一样：

```text
r_1 = r_2 = ... = r_G
```

那么中心化后的优势接近零。它无法告诉模型“这一组全错了，应该朝哪个未采到的方向走”。可验证奖励过稀时，这一点尤其明显。

#### 代价三：相对最好，不等于绝对正确

若奖励模型偏爱格式、长度或某种可钻漏洞的模式，GRPO 会稳定强化组内最会迎合这个偏好的回答。相对化能消掉共同难度，消不掉会改变组内排序的系统性偏置。

#### 代价四：样本并非真正独立

同一策略、同一 prompt、相近 decoding 设置产生的回答高度相关。名义上有 G 个样本，有效样本量可能远小于 G；增加组大小也未必线性增加信息。

*结构标注：全文主张的压力测试。“拿掉 critic”只是把估计误差从函数逼近迁移到组内采样与 reward ranking。*

#### 最强反驳

有人会说：“既然组均值这么噪，训练一个 critic 显然更好。”

不一定。critic 低方差，但可能有持续、相关的函数逼近偏差；组均值高方差，却更少依赖额外模型假设。真正的取舍不是“准确 vs 不准确”，而是：

```text
critic:  用跨样本泛化换低方差，承担模型偏差
GRPO:    用同题多采样换少建模，承担采样方差
```

这和昨天 GAE 的 bias-variance 账是同一本账，只是旋钮换了位置。

### 5. [肌] 什么时候 GRPO 合适？

更合适的场景：

- 一个 prompt 可以较便宜地采多条候选；
- 整段输出有可靠的标量奖励，尤其是数学、代码等可验证任务；
- prompt 难度差异大，组内相对化能消掉题目级共同项；
- value model 的训练与显存成本是主要瓶颈。

要谨慎的场景：

- 交互轨迹很长，真正需要逐状态、逐动作的 credit assignment；
- 奖励极稀疏，整组经常全 0 或全 1；
- 主观 reward model 的排序偏差很强；
- 单个 prompt 无法承担多次 rollout 的推理成本；
- 组内回答多样性不足，G 大但有效样本量小。

*结构标注：应用边界。以上 2 组条件支持“算法选择取决于可获得的比较轴”。*

## 全文复盘

### 理解轨迹

今天最值得带走的不是 GRPO 的公式，而是一个可迁移的诊断法：看到任何 policy-gradient 算法，先问三件事。

1. `R` 从哪里来？——环境、验证器还是 reward model？
2. baseline 从哪里来？——critic、组均值，还是别的控制变量？
3. 序列奖励怎样分到动作/token？——逐步回报、GAE，还是整段广播？

这三问能把“算法名字”还原成“估计器的选择”。

### 读后一句话（不可跳过）

*读完之后，你最想对“GRPO 不需要 Critic”这句宣传语补上的一句话是什么？*

我的候选回答不是标准答案：

> 它没有消灭“本来可以期待多少”这个问题，只是从 value model 的预测，换成了同题样本的相对位置。

### 终局问题

如果一组回答全错，组内相对优势仍会奖励“错得最少”的那个；那么训练系统需要什么机制，才能区分“局部相对改进”与“朝错误盆地越走越深”？

### 术语表

| 英文 | 中文 | 本文含义 | 位置 |
|---|---|---|---|
| baseline | 基线 | 与回报相减、用于降低梯度方差的参照 | 第 1 节 |
| control variate | 控制变量 | 保持期望、降低估计方差的统计技巧 | 第 1 节 |
| critic / value model | 价值模型 | 预测某状态下未来期望回报的模型 | 第 2 节 |
