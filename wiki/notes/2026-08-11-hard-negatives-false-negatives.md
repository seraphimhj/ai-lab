# 难负例不是“更难的数据”：它在悄悄改写检索模型学到的世界

*本次命中：RAG / 检索 / Embedding 主线，以及「数据 -> 采样 -> 目标函数 -> 评测 -> 线上分布」端到端闭环薄弱点。*

## 一句话摘要

在对比学习里，负例采样并非把既定 loss 喂得更饱，而是在定义“哪些差异值得模型在意”；难负例提供有效梯度，却也最容易混入假负例，因此真正的问题不是“负例够不够难”，而是“采样分布是否与线上决策边界一致”。

## 全局地图

Agent 判断：

- `[骨]` 对比学习只看到了被采到的局部世界，采样器因此是隐形目标函数。
- `[肌]` 随机负例、难负例、假负例分别产生“梯度太弱”“边界更锋利”“方向被写反”三种效果。
- `[骨]` 难度不是单轴；应把“模型相似度”和“语义有效性”拆开。
- `[肌]` BM25、在线挖掘、交叉编码器、同 query 去重等方法，本质上都在控制这两个轴。
- `[骨]` 训练闭环的终点不是离线 loss，而是线上候选集中的排序边界。

```text
数据池
  |
  v
负例采样器 ---------> 模型实际看到的局部世界
  |                         |
  |                         v
  |                   InfoNCE 梯度
  |                         |
  v                         v
难度 + 语义有效性 ----> 学到的决策边界
                            |
                            v
                     离线评测 / 线上候选集
                            |
                            +----> 反过来决定下一轮挖掘
```

核心因果链是：

```text
采到谁 -> 和谁比较 -> 梯度推开谁 -> 表示空间留下什么边界 -> 线上错在哪
```

## 第一段 `[骨]`：InfoNCE 优化的不是“全世界”，而是当前这一小撮候选

先看一个 query `q`、一个正例 `d+` 和若干负例 `d-`。检索训练常用的 InfoNCE 可以写成：

```text
L = -log [ exp(s(q,d+)/tau)
           / (exp(s(q,d+)/tau) + sum_i exp(s(q,d_i-)/tau)) ]
```

其中：

- `s(q,d)`：query 与文档的相似度；
- `tau`：温度，控制 softmax 对分数差异有多敏感；
- 分母：模型这一次被要求区分的候选集合。

容易忽略的是：分母并不包含语料库全部文档，只包含*采样器挑来的文档*。所以 loss 表面上在学习“正例优于负例”，实际上只在学习：

> *正例应优于这一次恰好出现在分母里的负例。*

如果某类错误文档从不进入分母，模型便几乎收不到“要避开它”的梯度。采样器由此决定了模型看到哪个局部世界。

*结构标注：核心论点。负例采样不是训练前的数据准备，而是目标函数的一部分。*

### 注疏：它和 DoReMi 的同构

前几天的 DoReMi 伴读讲过：数据配比通过改变各域获得梯度的频率，成为“隐形目标函数”。负例采样是同一个形状，只不过粒度从“哪个数据域”缩小到了“正例周围的哪条决策边界”。

```text
DoReMi:      哪个域更常出现       -> 模型更在意哪个域
负例采样:   哪种混淆项更常出现   -> 模型更在意哪种差异
```

### 碰撞问题

*假如训练 loss 已经很低，但线上总把同一产品的不同型号混在一起，应该先改模型结构，还是先检查“不同型号”是否进入过训练分母？*

## 第二段 `[肌]`：随机负例为什么常常“正确但没用”

假设 query 是：

> `MacBook Air M4 15-inch battery life`

随机抽到的负例可能是：

> `How to grow tomatoes on a balcony`

它当然是负例，但模型很早就能把两者分开。若正例分数已经明显更高，softmax 给这个随机负例的概率接近 0，它贡献的梯度也接近 0。

对单个负例 `d_i`，梯度方向可以粗略理解为：

```text
负例被模型认为越可能 -> softmax 概率越大 -> 推开它的梯度越强
```

所以容易负例的问题不是标签错，而是它位于决策边界之外。训练批次看似很大，大量位置却在提供近乎重复的“番茄不是电脑”信号。

随机负例仍有价值：便宜、覆盖广，并能维持全局几何结构。问题只在于，训练进入中后期后，它们不足以继续修细边界。

*结构标注：证据铺垫。解释为什么“更多负例”不等于“更多有效监督”。*

## 第三段 `[肌]`：难负例为什么有效——它把梯度预算花在边界附近

更有用的负例可能是：

> `MacBook Air M3 15-inch battery life`

它与 query 共享品牌、产品线、尺寸和任务意图，只错在型号。当前模型很可能给它高分，因此 softmax 会分配较大概率，loss 也会产生强梯度，迫使表示空间保留 `M4` 与 `M3` 的差异。

这正是难负例（hard negative）的价值：

```text
容易负例: 话题不同，离边界远，梯度弱
难负例:   表面相近，靠近边界，梯度强
```

但“模型觉得相似”只说明它难，不说明它真的是负例。这是下一段的陷阱。

*结构标注：机制说明。难负例通过提高候选概率，把训练信号集中到当前决策边界。*

以上两段在支持第一段的论证：采样器决定有限梯度预算被花在哪里。

## 第四段 `[骨]`：最难的负例，可能根本不是负例

仍以刚才的 query 为例。下面这段文档没有精确标题，却可能完整回答问题：

> `The 15-inch model with Apple's latest M4 chip lasted 15 hours in our test.`

如果标注系统只把某个点击文档记作正例，这一段可能因“未被点击”而被当成负例；如果用当前模型做近邻挖掘，它又恰好会被挖成最难的一批。于是训练告诉模型：

```text
query 与一个真正相关的文档很相似
             |
             v
标签却说：把它推远
```

这就是假负例（false negative）。它不是普通噪声，因为难负例恰好拥有较大的 softmax 权重，错误标签会得到*最强的反向梯度*。

因此存在一个危险的选择效应：

```text
越像正例 -> 越容易被 hard-negative miner 选中
越像正例 -> 也越可能其实相关
越难     -> 一旦标签错，破坏力越大
```

随机标签噪声可能互相抵消；被挖掘机制系统性放大的假负例不会。它会逼模型学会忽略同义表达、多答案和部分相关性，最后得到一个边界锋利但世界观狭窄的检索器。

*结构标注：关键转折。难负例提高有效梯度的机制，也同时放大了假负例的伤害。*

### 点睛：false negative 不是“错一点”

在二分类里，一个错标样本只是一个错误点；在对比学习里，它还占据分母并参与相对竞争。模型不仅没被奖励去接近它，还被明确要求把它推远。因此更准确的中文理解是：*被当成反例的真相关项*。

### 压力测试

有人会说：“那就只用随机负例，至少安全。”

最强反驳是：安全地提供零梯度，同样学不到线上真正需要的细粒度边界。问题不是取消 hard negative，而是把“难”和“真负”分开控制。

## 第五段 `[骨]`：把一根“难度轴”拆成两根轴

负例不应只按模型相似度排序。更稳健的框架有两个维度：

```text
                     语义有效性
                 低                 高
模型相似度  高   危险区             黄金区
               假负例风险高       真正难负例

           低   低价值区           可用但梯度弱
               无关随机项         容易真负例
```

这里的“高语义有效性”指：有足够证据确认它确实不能满足 query，而不只是没有被标成正例。

于是理想训练集不是“相似度最高的 top-k”，而是：

> *位于当前模型边界附近，同时有较高置信度确为不相关的文档。*

这也解释了常见方法各自在做什么：

1. *BM25 难负例*：用词面重叠找到容易混淆的候选，避免全是跨话题随机项；但同义答案可能漏掉，且高重叠文档也可能相关。
2. *Dense 在线挖掘*：用当前模型的近邻暴露它自己的盲点；但模型越强，top 邻居中潜在真相关项越多。
3. *Cross-encoder 过滤*：让联合编码器复核候选，把疑似相关项从负例中排除；代价是教师偏差和额外计算。
4. *同 query 多正例去重*：已知相关文档不允许互为 in-batch negative，避免最直接的标签冲突。
5. *半难负例（semi-hard negative）*：不取最相似的尖端，而在一个相似度区间采样，牺牲一点梯度强度来降低假负例率。
6. *软标签或多级相关性*：不把世界硬切成 0/1，而让“部分相关”承受较小的推离力度。

*结构标注：解决框架。负例质量等于“有梯度价值”与“标签可信度”的联合问题。*

## 第六段 `[肌]`：in-batch negatives 的隐藏前提

双塔训练常把同一 batch 中其他样本的正例当作当前 query 的负例。这样几乎不增加编码成本，就能让 batch size 为 `B` 时，每个 query 获得约 `B-1` 个负例。

它隐含了一个前提：

> *不同训练样本的正例彼此不相关。*

在开放域问答、FAQ、商品搜索里，这个前提经常不成立：两个 query 可能是同义问法；同一文档可能回答多个 query；同系列商品可能同时满足宽泛需求。

更大的 batch 一方面增加负例数量，另一方面也提高语义碰撞概率。因此 batch size 不是单纯的“越大越好”，还会改变假负例率。

可行修法包括：按 query 或实体簇去重、屏蔽已知相关对、用教师模型过滤、对可疑负例降权。共同点是：不把“没配对”自动等同于“不相关”。

*结构标注：边界条件。揭示高效训练技巧背后的标签假设。*

## 第七段 `[骨]`：闭环——线上候选集才是训练目标的真实考场

现在把链条接完整：

```text
线上请求分布
  |
  v
召回器产生的真实混淆项
  |
  v
失败切片：实体 / 型号 / 时间 / 数字 / 多答案
  |
  v
定向挖掘 + 相关性复核
  |
  v
对比学习更新边界
  |
  v
新的召回器改变下一轮候选分布
```

这不是一次性造数据，而是一个闭环。模型更新后，旧难负例可能已经变容易；新的近邻又会暴露新的盲点。因此 ANCE 一类方法会异步刷新索引和负例，使采样分布跟随模型变化。

但只让模型追逐自己的 top 近邻，会形成反馈回路：它看不到的错误永远挖不到，它误认为相似的样本被反复强化。要打破这个回路，需要混合来源：随机负例维持覆盖，BM25 提供词面混淆，dense miner 暴露模型盲点，线上日志提供真实候选，人工或强教师保证语义有效性。

最后，离线评测也必须与这套目标对齐：

- 只看随机候选上的 Recall，可能掩盖细粒度混淆；
- 只看单一标注正例，会把未标注真相关项误判为错误；
- 只报总体均值，会掩盖实体、型号等少数但关键切片；
- 最好同时看全库检索、hard slice、去重后的多正例指标和线上行为。

*结构标注：全文收束。数据、采样、目标函数、评测和线上分布构成会自我改变的系统。*

```text
现象                         优先检查                         不要先做什么
loss 很快趋近 0              负例是否过易                     盲目加 epoch
训练指标升、全库召回不升     候选分布是否与全库不一致         只调温度 tau
近邻越来越同质               hard miner 是否自我强化          只取 top-k 最近邻
同义问法互相排斥             in-batch 中是否存在假负例         单纯扩大 batch
实体/型号错误多              是否采到同类不同实体负例          立刻换更大模型

离线升、线上降               线上候选与离线负例分布是否错位   相信总体均值
```

## 一个最小可执行配方

如果要训练一个生产级检索双塔，可以从以下混合开始，而不是追求单一“最强 miner”：

```text
每个 query 的负例池
  25% 随机负例       -> 保持全局覆盖
  25% BM25 难负例    -> 强化词面近似下的语义区分
  25% dense 难负例   -> 暴露当前模型自己的混淆边界
  25% 线上候选负例   -> 对齐真实服务分布

进入 loss 前：
  已知正例屏蔽
  + 同 query / 同实体去重
  + cross-encoder 或人工规则过滤疑似真相关项
  + 对高风险候选使用软权重
```

这里的比例只是起点，不是普适答案。真正应监控的是每一类负例的：模型分数分布、人工真负率、梯度贡献、对应线上失败切片收益。

## 今天真正要带走的一点

不要把 hard negative 理解成“更难的训练题”。它更像是在告诉模型：

> *未来做决定时，哪一种差异必须成为边界。*

于是负例采样承担了三重角色：

```text
数据选择器 + 梯度路由器 + 世界观编辑器
```

采错容易负例，模型学不到；采错假负例，模型学反了；只采当前模型认得的难例，模型会被自己的盲点困住。

## 读后一句话

读完后，请在心里补完这句：

> *我现在会把负例采样看成 ______，而不只是 ______。*

如果答案只是“选数据”，还差半步；如果你想到“它在定义局部目标和线上决策边界”，这篇就真正接上了端到端闭环。

## 终局问题

*当一个检索系统只能通过点击日志判断正负，而“未点击”同时混合了不相关、没曝光、排位太低和用户已被前文满足四种原因时，你要怎样设计采样与 loss，才不会把曝光机制的偏差写进 embedding 空间？*

这道题把今天的负例采样，接到了下一层：反事实学习与选择偏差。

## 术语表

| 英文 | 中文 | 本文含义 |
|---|---|---|
| negative sampling | 负例采样 | 决定哪些候选进入对比学习分母的机制 |
| hard negative | 难负例 | 当前模型容易误判为相关、但经确认确为不相关的候选 |
| false negative | 假负例 | 实际相关，却被训练标签当作负例的候选 |
| in-batch negative | 批内负例 | 把 batch 中其他样本的正例复用为当前 query 的负例 |
| semi-hard negative | 半难负例 | 靠近边界但避开最高相似度尖端的负例 |
| negative mining | 负例挖掘 | 用 BM25、当前模型或线上日志发现高价值负例 |
| selection bias | 选择偏差 | 被观察或采到的数据并非从目标分布随机产生 |
