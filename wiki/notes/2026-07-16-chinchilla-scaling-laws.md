# 伴读：数据和参数怎么分钱——Chinchilla 与 Scaling Laws

> 本次命中：薄弱点「retrieval 以外·大模型预训练」与「端到端闭环·数据环节」；重点不是记住“20 tokens/参数”，而是把整篇论文看成一个固定算力下的约束优化问题。

来源：Hoffmann et al., *Training Compute-Optimal Large Language Models*, NeurIPS 2022, arXiv:2203.15556。

# 全局地图

## 一句话摘要

给定训练算力，不要本能地把钱全花在更多参数上：参数量 N 和训练 token 数 D 是两种争夺同一预算的资源，最优点在“模型容量不足”和“数据训练不足”两种误差的边际收益相等处。

## 结构地图

```text
固定预算 C
   |
   +-- 选择参数量 N -------- 降低容量不足误差
   |
   +-- 选择 token 数 D ----- 降低训练不足误差
   |
   +-- 约束：C ~= 6 N D
             |
             v
      拟合 L(N, D)
             |
             v
   求约束下损失最小的 (N*, D*)
             |
             v
  70B Chinchilla + 1.4T tokens
  对照 280B Gopher + 300B tokens
             |
             v
  同级算力下，小而充分训练的模型更强
```

## 段落分类概览（Agent 判断）

- [骨] 问题重写：scaling 不是“模型该多大”，而是“固定算力怎么在 N 与 D 之间分配”。
- [肌] 实验设计：训练 400 多个模型，覆盖约 70M 至 16B 参数、5B 至 500B token，并用三种方法估计最优前沿。
- [骨] 数学骨架：C 约等于 6ND；L(N,D) 可拆成不可约损失、参数不足项和数据不足项。
- [肌] 实证验证：用约 70B 参数、1.4T token 的 Chinchilla 对比 280B、约 300B token 的 Gopher。
- [骨] 推论与边界：20 tokens/参数是特定实验设定下的经验工作点，不是跨数据质量、训练轮数和推理成本的自然常数。

# 逐段伴读

## 1. [骨] 作者真正改写了什么问题

**原文**

> “We investigate the optimal model size and number of tokens for training a Transformer language model under a given compute budget.”

**直译层（信）**

> “我们研究：在给定计算预算下，训练 Transformer 语言模型时，最优的模型规模和 token 数量是多少。”

**意译层（达）**

旧问题是：“预算增加后，模型应该做多大？”

Chinchilla 把它改成：“每一单位算力，是拿去增加一个参数，还是让已有参数多看一个 token？”

这不是措辞变化，而是把单变量 scaling 改成双变量资源配置：

- N：参数量，代表模型可以容纳多少结构与规律；
- D：训练 token 数，代表这些参数获得多少证据来确定自身取值；
- C：总训练算力，是硬预算。

**结构标注**：核心问题；全文后面的实验和公式都在回答这个约束优化题。

**先停一秒**

如果把模型想成一家公司：参数是员工数量，token 是员工处理过的案例。员工多但案例少，会发生什么？不是公司“容量”不够，而是大量员工尚未形成经验。2022 年以前不少大模型正处于这种状态。

## 2. [肌] 论文为什么训练 400 多个模型

**原文**

> “By training over 400 language models ranging from 70 million to over 16 billion parameters on 5 to 500 billion tokens...”

**直译层（信）**

> “通过训练 400 多个语言模型，参数规模从 7000 万到 160 多亿，训练 token 数从 50 亿到 5000 亿……”

**意译层（达）**

作者不是只比较两个成品模型，而是在二维平面上采样：横轴是 N，纵轴是 D，每个点都对应一次真实训练，再观察固定计算量的等预算曲线上，哪个点的验证损失最低。

```text
D（更多数据）
^
|            x
|        x       x
|    x       o       x     o = 某条等算力曲线上的最低损失点
| x      x       x
+-------------------------> N（更多参数）
```

论文用了三种相互校验的方法：

1. 固定若干计算预算，直接找每条等算力曲线的最低点；
2. 对每个模型规模看训练曲线，寻找不同预算下的最优点；
3. 拟合参数化损失函数 L(N,D)，再解析或数值求最优解。

三条路的价值不是“投票取平均”，而是防止某一种拟合假设独占结论。

**结构标注**：证据铺垫；以上实验支撑“参数与数据应更均衡地扩展”的骨架结论。

## 3. [骨] 一条预算约束：为什么是 C ~= 6ND

对标准 dense Transformer，训练计算量常近似写成：

```text
C ~= 6 N D
```

其中：

- C：训练 FLOPs；
- N：非 embedding 参数量的近似规模；
- D：训练 token 数；
- 6：一次 token-参数交互在前向与反向传播中的粗略常数。

别把 6 当物理常数。真正重要的是乘积关系：

```text
固定 C  =>  N D 基本固定
```

因此 N 翻倍而预算不变，D 就必须减半。你不能同时免费拥有更多参数和更多数据。

以“20 tokens/参数”这个 Chinchilla 经验工作点作粗略规划：

```text
D = 20N
C = 6ND = 120N^2

所以：
N = sqrt(C / 120)
D = 20 sqrt(C / 120)
```

例如 C = 10^23 FLOPs 时，粗算得到：

```text
N ~= 28.9B 参数
D ~= 577B tokens
```

这一步最值得带走：scaling law 首先是预算表，不是模型排行榜。

**结构标注**：约束条件；它把“更大模型”和“更多数据”变成明确的此消彼长。

## 4. [骨] 损失函数：三种误差为什么能相加

论文的一种参数化形式是：

```text
L(N,D) = E + A / N^alpha + B / D^beta
```

首次出现的术语：

- irreducible loss（不可约损失）E：即使模型和数据无限增大，在给定数据分布与 tokenization 下仍剩余的预测不确定性；
- model-size term（参数规模项）A / N^alpha：模型容量有限造成的损失；
- data-size term（数据规模项）B / D^beta：训练证据有限造成的损失。

**直觉翻译**

```text
总损失
= 世界本来就难预测
+ 模型装不下
+ 模型没学够
```

这和你之前建立的“统一目标函数”视角可以接上：交叉熵仍是被测量的训练/验证目标，scaling law 不是发明一个新 loss，而是在经验上拟合“最优交叉熵如何随资源 N、D 下降”。

论文报告的一组拟合大致为：

```text
E = 1.69
A = 406.4
B = 410.7
alpha = 0.34
beta  = 0.28
```

这里真正有用的不是背系数，而是两个幂指数都小于 1：资源翻很多倍，损失只按幂律缓慢下降，边际收益递减。

**结构标注**：核心模型；它把“容量不足”和“训练不足”分离成两张可比较的账单。

## 5. [骨] 最优点不是两项相等，而是边际收益相等

把预算约束 D = C / (6N) 代入损失：

```text
L(N) = E + A / N^alpha + B (6N / C)^beta
```

此时增大 N 会同时发生两件事：

- 参数不足项下降；
- 因为 D 被迫减少，数据不足项上升。

最优 N* 出现在导数为零的位置。忽略常数后：

```text
N* proportional to C^[ beta / (alpha + beta) ]
D* proportional to C^[ alpha / (alpha + beta) ]
```

代入 alpha = 0.34、beta = 0.28：

```text
N* proportional to C^0.452
D* proportional to C^0.548
```

也就是说，算力翻倍时，这组参数化拟合预测：

```text
N* 约乘 1.37
D* 约乘 1.46
```

论文另外两种估计方法得到接近“二者随算力近似等速扩展”的结果。不要把 0.452/0.548 和“等速”看成矛盾：400 多次有限规模实验只能估出一段区间内的经验前沿，三种方法的精确指数不同，但共同推翻了“主要扩参数、数据增长很慢”的旧分配。

**点睛**

最优条件不是：

```text
参数误差 = 数据误差
```

而是：

```text
最后一单位算力投给参数所减少的损失
=
最后一单位算力投给数据所减少的损失
```

这就是经济学里的边际收益相等。Scaling law 本质上是一道资源配置题。

**结构标注**：全文的数学心脏；从经验损失面推出 compute-optimal allocation（算力最优分配）。

## 6. [肌] Gopher 与 Chinchilla：不是“小模型逆袭”，是预算重新分配

**原文**

> “Chinchilla ... uses the same compute budget as Gopher but with 70B parameters and 4x more data.”

**直译层（信）**

> “Chinchilla 使用与 Gopher 相同的计算预算，但参数为 700 亿，并使用 4 倍多的数据。”

**意译层（达）**

Gopher 把更多预算放在参数上；Chinchilla 把模型缩到约四分之一，再把释放出的训练计算用于看更多 token。

粗账如下：

```text
Gopher:     N ~= 280B, D ~= 300B,  D/N ~= 1.07
Chinchilla: N ~=  70B, D ~= 1.4T,  D/N = 20
```

按 C ~= 6ND 粗算：

```text
Gopher:     C ~= 5.04 x 10^23 FLOPs
Chinchilla: C ~= 5.88 x 10^23 FLOPs
```

二者并非逐 FLOP 完全相同，这个近似也忽略不少架构与记账细节；但属于同一计算量级。关键实验结果是：Chinchilla 在大量下游任务上优于更大的 Gopher，同时推理时只需携带四分之一左右的参数。

**结构标注**：验证实验；把拟合出的最优点变成真实的大规模模型对照。

## 7. [筋] 作者从训练最优过渡到部署含义

更小而训练更充分的模型不仅训练损失更好，还往往减少推理时的参数读取、显存占用与延迟；作者由训练预算问题过渡到模型生命周期的总成本问题。

**结构标注**：从训练结论连接到推理系统。

## 8. [骨] 最容易误学的结论：“永远 20 tokens/参数”

20:1 是有用的基线，不是自然定律。至少五件事会移动最优点：

1. **数据质量**：1 个高质量 token 和 1 个重复、污染 token 不等价。D 只计数量，会隐藏信息密度。
2. **重复训练**：独立新 token 与同一语料多 epoch 的收益不同，数据不足项不能只看计数。
3. **架构变化**：MoE、参数共享、稀疏激活会改变 N 与实际计算的关系。
4. **训练目标变化**：tokenization、数据混合、优化器和训练稳定性会改变拟合系数。
5. **部署目标变化**：论文优化的是给定训练算力下的损失；若模型要服务数十亿次请求，更小模型的推理节省可能值得投入更多训练 token，甚至故意偏离 training-compute-optimal 点。

所以要区分三种“最优”：

```text
训练算力最优：固定 pretraining FLOPs，验证损失最低
推理成本最优：固定质量，单次或总 serving 成本最低
全生命周期最优：训练 + 存储 + 推理 + 数据成本最低
```

Chinchilla 直接回答第一种，并顺带让第二种变好；它没有替你解决第三种。

**结构标注**：边界条件；防止把局部经验规律误当成普遍配方。

# 一次碰撞：如果数据不是同质 token，D 应该是什么？

这里的论证结构和 RAG 很像：

```text
预训练 scaling：更多 token 不等于更多有效信息
RAG retrieval： 更多文档不等于更多有效证据
```

两边都把一个不可直接观察的量，用容易计数的代理量代替：

```text
有效训练信息  -> 用 token 数 D 代理
有效检索证据  -> 用召回条数 k 代理
```

一旦数据质量下降、重复增加，D 继续增长但“有效 D”增长变慢。于是更成熟的端到端问题不是“需要多少 token”，而是：

```text
每单位采集、清洗与训练成本，能带来多少新的可学习信息？
```

这正是数据环节向目标函数和评测环节传导偏差的位置：如果预训练语料的有效多样性被高估，拟合会建议继续加数据；如果 benchmark 又与语料污染重叠，评测还可能把这种错误配置伪装成进步。

# 压力测试

最强反驳可以这样说：

> “既然 Chinchilla 只在有限模型规模、特定数据分布和 2022 年架构上拟合，外推到更大模型并不可靠；所谓 20:1 可能只是一次历史性过拟合。”

这个反驳击中了“精确比例”，但没有击倒核心框架。即便 20 变成 10、40 或随规模变化，仍然必须回答：在固定预算下，增加 N 与增加有效 D 的边际收益分别是多少？

因此论文最耐久的遗产不是数字 20，而是下面这张决策表：

```text
观察                            诊断                 下一笔预算
参数增大仍显著降 loss           容量不足             倾向增加 N
延长训练仍显著降 loss           训练不足             倾向增加 D
新数据收益低、重复收益饱和       有效数据不足          提升质量/多样性
训练已足但 serving 太贵          生命周期目标错位      缩小 N、增加训练
离线 loss 好但下游/线上差         数据分布或评测错位    查数据混合与评测
```

## 终局问题

当 token 的“信息价值”不同、模型还会服务不同数量的请求时，是否应该把 Chinchilla 的二维优化升级成三维甚至四维：参数 N、有效数据 D_eff、训练计算 C_train、累计推理计算 C_infer？如果这样做，今天所谓的“基础模型最优规模”还会是一个固定数字吗？
