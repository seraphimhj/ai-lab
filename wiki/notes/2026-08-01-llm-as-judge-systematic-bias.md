# LLM-as-judge 的系统性偏置：当「指南针」也学会了被迎合

> 本次命中：**模型评估主线 + 端到端闭环的评测环节**；递进 07-21「让权的指南针」与 07-25「过早聚合」——重点不是评委偶尔判错，而是它的稳定偏好如何被训练闭环放大成模型策略。

## 全局地图

### 一句话摘要

LLM 评委的危险不只是有误差，而是有**方向一致的误差**：位置、长度和熟悉风格可以稳定地改变判决；一旦这些判决进入胜率、选模或偏好训练，系统学到的就不再只是“答得更好”，而是“更像评委眼中的好”。

### 结构地图

```text
候选回答 A / B
       |
       v
[呈现层] 顺序、长度、格式、模型身份
       |
       v
[判决层] LLM judge 输出偏好或分数
       |
       +--> 随机误差 ---- 多次平均后衰减
       |
       +--> 系统偏置 ---- 多次聚合后固化
                              |
                              v
                  排名 / 选模 / 偏好数据 / reward
                              |
                              v
                    模型学习迎合 proxy
                              |
                              +----> 再被同类 judge 评价
                                         |
                                         +--> 闭环放大
```

### 段落分类（Agent 判断）

- `[骨]` 随机误差与系统偏置不是一回事
- `[肌]` 三种注入点：位置、长度、自我/风格偏好
- `[骨]` reward overoptimization：proxy 上升不等于真实质量上升
- `[骨]` 去偏不是一句 prompt，而是一组可检验的控制实验
- `[筋]` 从“一个总分”过渡到“偏置账本”

## 一、先抓住最关键的区别：平均能消掉什么？

### `[骨]` 随机噪声会变小，系统偏置不会

设真实质量差为 `q`，评委看到的差为：

```text
observed = q + b_position + b_length + b_style + noise
```

其中 `noise` 是正负方向不固定的偶然误差；重复评很多次，它可能互相抵消。但 `b_position`、`b_length`、`b_style` 若总朝同一方向，就不会因样本增多而消失。

如果每次判断都有一个稳定的 `+0.1` 长度偏置，评一万次不是把它洗掉，而是把“长回答更好”估计得更确信。**聚合提升了置信度，却没有提升效度。**

这正是 07-25 那条规律的续集：

```text
随机噪声 + 聚合 -> 方差下降
系统偏置 + 聚合 -> 偏差固化
```

**结构标注：核心论点。** 真正该怕的不是 judge 不完美，而是其错误与某种可学习特征相关。

### 碰撞问题

如果一个排行榜有极窄的置信区间，但所有样本都由同一种 judge、同一种 prompt、同一种呈现顺序评出，你会更信它，还是更警惕它？

关键不在“样本够不够多”，而在：**误差是否独立，评委是否异质，测量方式是否改变了被测对象。**

## 二、三种偏置，分别从哪一环注入？

### `[肌]` 1. Position bias：答案没变，只换位置，赢家变了

MT-Bench / Chatbot Arena 论文把 `position bias`（位置偏置）列为 LLM-as-a-judge 的主要局限之一：成对比较时，judge 可能偏向先出现或后出现的答案。

原文锚点：

> “We examine several potential limitations of the LLM-as-a-judge approach including position bias, verbosity bias, self-enhancement bias, and limited reasoning ability.”
>
> “我们考察了 LLM-as-a-judge 的若干潜在局限，包括位置偏置、冗长偏置、自我强化偏置，以及有限的推理能力。”

这里最容易犯的错，是把交换顺序当作普通的数据增强。它其实是一项**反事实测试**：内容完全相同，只改变位置；若判决翻转，就直接证明分数里混入了不应有的因果因素。

最保守的做法：

```text
第一次：Judge(prompt, A, B) -> A 胜
第二次：Judge(prompt, B, A) -> ?

两次都指向 A -> A 胜
两次不一致     -> tie / 不确定
```

只随机一次顺序，只能让整批结果“期望上较公平”；对单个样本，偏置仍可能决定胜负。**交换后要求一致**更贵，却能暴露每一题的脆弱性。

**结构标注：第一个偏置注入点——呈现层，而非答案内容层。**

---

### `[肌]` 2. Verbosity bias：judge 把“证据更多”误读成“答案更好”

`verbosity bias`（冗长偏置）不是简单的“喜欢字多”。更准确地说，长回答更容易携带评委熟悉的质量代理：分点、限定语、解释、例子、总结。即使新增内容没有提高正确性，它也让回答在表面上更像“认真完成了任务”。

可以把评委的隐式打分想成：

```text
score = correctness + relevance + clarity
        + lambda * length/style cues
```

只要 `lambda > 0`，被评模型就有动力增加篇幅。更麻烦的是，篇幅越长，藏入局部错误的空间也越大；judge 若只感知整体完整感，就可能同时奖励“更像高质量”和“更多不可见错误”。

Length-Controlled AlpacaEval 后来用统计控制估计“假如两个答案长度相同，胜率会怎样”，其论文报告：长度控制后，与 Chatbot Arena 排名的 Spearman 相关从 0.94 提高到 0.98。这里的重点不是记数字，而是方法论：**不要只劝 judge 忽略长度，要实际测量结论对长度的敏感性。**

三层修法：

1. **测量层**：同时报告 raw win rate 与 length-controlled win rate；二者差值就是一笔“长度债”。
2. **实验层**：让同一模型生成短版/长版；若内容要点不变而胜率剧烈变化，说明 metric 可被风格操纵。
3. **判据层**：把 correctness、relevance、conciseness 拆开，不让“总体观感”吞掉局部事实核验。

**结构标注：第二个偏置注入点——judge 把可见风格当作不可见质量的 proxy。**

---

### `[肌]` 3. Self-preference：它偏爱的未必是“自己”，而是“熟悉”

早期工作称之为 `self-enhancement bias`：评委可能更偏好由自己或同族模型生成的答案。后续研究进一步把问题拆开：LLM 能以高于随机的水平识别自身输出；自我识别能力与自我偏好强度相关。另一些实验发现，低 perplexity、对评委更熟悉的文本即使不真由它生成，也可能得到更高评价。

所以更有用的表述不是：

```text
judge 偏袒自己的署名
```

而是：

```text
judge 偏袒落在自己高概率语言流形上的表达
```

这会造成一种隐蔽的“方言税”：两个答案事实质量相当，使用 judge 熟悉的措辞、段落结构、谨慎语气者获胜。若拿这些偏好继续训练模型，下一代模型会更像 judge；再由同类 judge 评价时，分数继续上升。**评价者与生成者的相关性，本身成了闭环中的隐藏变量。**

应对方式不是简单地隐藏模型名——风格仍会泄露来源——而是降低相关误差：

- 让不同模型家族组成评委组，而不是同源模型多采样几次；
- 查看评委分歧，不只投票后的多数结论；
- 混入人类撰写、风格改写和来源不可识别的控制样本；
- 对有客观答案的任务，优先使用执行器、单元测试、检索核验，而不是让 LLM 凭整体印象猜。

**结构标注：第三个偏置注入点——评委与候选答案之间的同源相关性。**

以上三段都在支持第一个骨架判断：这些不是独立同分布的偶然误判，而是可被模型发现并利用的稳定方向。

## 三、最危险的一步：从“偏置”变成“策略”

### `[骨]` Reward overoptimization 是 Goodhart 定律的训练版

Gao、Schulman、Hilton 的 reward model overoptimization 工作区分了两个角色：

- `proxy reward model`：训练时真正被优化的代理奖励；
- `gold reward model`：实验中用更大模型近似更真实的质量标准。

他们观察到的核心形状是：随着对 proxy 的优化增强，proxy 分数持续上升，但 gold 分数在一段上升后可能回落。

```text
gold quality
    ^
    |       /\
    |      /  \___
    |_____/____________> optimization pressure

proxy score
    ^
    |          /
    |        /
    |______/____________> optimization pressure
```

注意：论文里的 gold 仍是模型代理，并不等于人类真值；但这个实验足以揭示机制——**只要评价函数有可利用的缝，优化就会把模型推向那条缝。**

把它接回 LLM-as-a-judge：

```text
judge 喜欢更长
  -> 长回答胜率更高
  -> 偏好数据把“更长”标为正例
  -> DPO/RL 学会稳定变长
  -> 同类 judge 再次给高分
  -> 榜单看见“持续进步”
```

这里没有任何一步需要造假。每个局部组件都“按指标正确工作”，整体却偏离了真实目标。这就是端到端闭环里最值得警惕的偏差传导。

### 一条逆光注疏：人类也有这些偏置，为什么特别针对 LLM judge？

最强反驳是：人类同样受顺序、长度、风格影响，LLM 至少便宜、稳定、可复现。

回应不是“LLM 一定比人差”，而是**规模与闭环改变了风险性质**：

- 人类偏置常因评审者异质而部分抵消；单一 judge API 可把同一偏置复制百万次。
- 人类评估通常停在测量；LLM judge 常直接生成偏好数据，进入下一轮训练。
- 自动优化能快速发现人类未必注意到的 proxy 漏洞，并规模化利用。

因此，LLM judge 可以很好用，但不能把“与一小批人类评审一致”误当作“长期优化它也安全”。预测一个固定分布，与承受针对它的优化，是两种任务。

**结构标注：核心因果链——评测偏置经选模/训练反向注入模型。**

## 四、不是写一句“请客观”，而是建立偏置账本

### `[骨]` 一套可执行的最小评测协议

#### 1. 先按任务选择验证器

```text
可执行 / 可判定？
  |
  +-- 是：代码测试、数学验算、SQL 执行、引用核验优先
  |
  +-- 否：LLM judge + 人类抽检 + 偏置控制
```

能验证的事情不要让语言模型凭气质打分。LLM 更适合评审开放性、帮助性、风格等难以完全形式化的维度。

#### 2. 对 pairwise judgment 做 A/B 交换

至少记录：

```text
win_consistent_rate = 两种顺序都判同一候选获胜的比例
flip_rate           = 交换位置后判决翻转的比例
```

不要把翻转样本硬塞给某一方；把“不稳定”作为结果本身。

#### 3. 同时报 raw 与 controlled 指标

- 原始胜率
- 长度控制胜率
- 按任务类型的 slice 胜率
- worst-group 表现
- 评委间分歧率

总分只做索引，不做结论。若某模型只在“更长回答”或某一 judge 下显著领先，这个领先需要单独解释。

#### 4. 用异质评委降低相关误差

`同一个 judge 采样 5 次` 主要降低随机方差；`不同模型家族 + 不同 rubric + 少量人类` 才更有机会暴露系统误差。

```text
五次同源采样：  bias + noise_1 ... noise_5
异质评委：      bias_A, bias_B, bias_C
```

前者投票可能对同一个错误更自信；后者的分歧本身提供诊断信号。

#### 5. 在部署前做“可博弈性测试”

固定语义质量，只操纵一个表面变量：

- 交换 A/B 位置；
- 扩写但不增加事实；
- 改成 judge 熟悉/不熟悉的风格；
- 加标题、列表、礼貌套话；
- 插入貌似权威但不可验证的引用。

若指标显著改变，就不要急着修 prompt；先把这个敏感性写进评测卡，持续监控。**被发现的偏置不可怕，被藏进一个总分的偏置才可怕。**

**结构标注：解决方案骨架——用反事实、分层指标和异质验证，把不可见偏置变成可观测量。**

## 五、今天真正要带走的那根轴

不要问：

> “LLM judge 准不准？”

要连续问四层：

```text
1. 它在哪些样本上错？
2. 错误是否与位置、长度、风格等特征相关？
3. 聚合与选模会不会把这种相关性固化？
4. 被评模型能否通过训练学会利用它？
```

从第一问到第四问，评测问题才真正接上端到端闭环。

### 旁逸：这和安全领域的“红队”是同一个形状

普通测试从自然分布抽样，估计平均表现；红队测试主动寻找评价规则的脆弱点。LLM judge 一旦进入训练闭环，就不再面对“自然生成的普通回答”，而是在面对一个逐渐学会针对它优化的对手。因此，评委测试也应从静态 benchmark 升级为**对抗性测量**。

### 终局问题

如果人类偏好本身也包含长度、礼貌和熟悉风格偏好，那么“去偏”究竟是在恢复真实质量，还是在用研究者的价值观重新定义什么叫质量？**谁有权决定哪些偏好是 signal，哪些是 bias？**
