# 伴读：InfoNCE 与 KL loss 同时学习，冗余吗？

> 本次命中：**统一数学框架**，并接上 **RAG / Embedding** 主线；直接回应你昨天留下的“InfoNCE 与 KL loss 同时学习是否冗余”。

## 全局地图

### 一句话摘要

InfoNCE 和 KL 都能写成“让一个预测分布接近目标分布”，但是否冗余不看公式名字，而看它们是否在约束**同一个随机变量、使用同一种教师信号、要求同一种几何结构**。

### 结构地图

```text
共同骨架：分布匹配
        |
        +-- InfoNCE：在候选集合上回答“谁更像谁？”
        |             主要塑造相对排序与表示空间
        |
        +-- KL：让学生分布贴近目标/教师分布
                      可传递软概率、暗知识与校准信息
        |
        +-- 是否冗余？
              |
              +-- 同一对象 + 同一目标 + 同一粒度 -> 大多冗余
              +-- 不同对象 / 目标 / 粒度         -> 可能互补
```

## 第一段 `[骨]`：先把两个名字压到同一副骨架

设一个 query 是 q，候选文档为 d1 到 dK。模型先计算相似度分数：

```text
si = sim(q, di) / temperature
```

再把分数变成候选集合上的概率：

```text
p(i | q) = exp(si) / sum_j exp(sj)
```

如果第 1 个候选是唯一正样本，InfoNCE 的损失就是：

```text
L_InfoNCE = -log p(1 | q)
```

把目标写成一个 one-hot 分布 y：正确候选概率为 1，其余为 0，那么它也可以写成：

```text
L_InfoNCE = CrossEntropy(y, p)
           = KL(y || p) + H(y)
```

因为 one-hot 目标的熵 H(y) 为 0，所以在这个特例里：

```text
InfoNCE = 目标为 one-hot 的 KL
```

**结构标注：核心统一。** InfoNCE 并不是 KL 的异类；它本来就是 softmax 交叉熵家族中的一个成员。

### 注疏：名字为什么仍然不同？

名字强调的是不同视角：

- **InfoNCE** 强调任务构造：一个正样本与若干负样本之间的对比，并带有互信息下界的历史来源。
- **交叉熵** 强调可优化的损失形式。
- **KL 散度** 强调两个分布之间的差异。

这与昨天的结论完全同构：MLE 是原则，NLL/交叉熵是优化形式，KL 是分布解释。今天只不过把预测对象从“下一个 token”换成了“哪个候选更匹配”。

### 碰撞问题

> “InfoNCE 与 KL 不同”这句话里，所谓“不同”究竟指公式、目标分布，还是训练数据的构造？

若不先指定这一点，讨论“是否冗余”会被损失函数的名字带偏。

## 第二段 `[骨]`：InfoNCE 主要教的是相对排序

InfoNCE 对一个 query 提出的核心要求是：

```text
正样本分数 > 当前候选集合中负样本的分数
```

更准确地说，它希望正样本在 softmax 后占据尽可能大的概率。它不直接要求某个相似度必须等于固定数值，也不直接规定整个语料库的全局概率分布。

这带来三个关键性质：

1. **监督是集合相对的。** 同一个正样本，放进不同负样本集合，梯度会不同。
2. **难负样本决定学习强度。** 已经远离的负样本贡献很小；与正样本混淆的负样本贡献最大。
3. **batch 就是隐含课程表。** SimCLR 用同一图像的两种增强作正对，batch 内其他图像作负对；Sentence-BERT 常用句对和 batch negatives；E5 则通过弱监督文本对和指令前缀，让通用检索任务共享同一表示空间。

**结构标注：概念拆解。** InfoNCE 不只是一个公式，它还把“正负样本怎样出现”编码进了训练目标。

### 一个容易漏掉的点：温度不是装饰

温度越低，softmax 越尖锐，模型更关注最难的少数负样本；温度越高，概率更平缓，更多候选参与梯度。因此温度实际上决定了“错误排序要被惩罚得多集中”。

```text
低温：像严格的名次考试，第一名之争最重要
高温：像看完整成绩分布，次序和差距都参与
```

### 碰撞问题

> 如果两套训练都用了 InfoNCE，但负样本采样完全不同，它们真的是“同一个目标”吗？

形式相同不等于学习信号相同。对检索模型而言，采样分布经常比损失函数名字更决定模型最终会什么。

## 第三段 `[骨]`：KL 可能提供 InfoNCE 没有的“软结构”

现在假设不是只有一个 one-hot 正确答案，而是有一个教师分布 t：

```text
teacher: [0.65, 0.25, 0.08, 0.02]
student: [0.40, 0.35, 0.15, 0.10]

L_KL = KL(t || student)
```

教师不仅说“第一个最好”，还说：第二个其实也很相关，第三个勉强相关，第四个才明显不相关。

普通的单正样本 InfoNCE 目标却是：

```text
target: [1, 0, 0, 0]
```

这会把“次相关文档”与“完全无关文档”都压成 0。于是 KL 蒸馏可能传递三种额外信息：

- **候选之间的细粒度相关性**：不仅是谁赢，还包括差多少。
- **教师的暗知识**：哪些错误彼此更接近。
- **概率校准**：分数是否能表达可信度，而不仅是排序。

**结构标注：关键分叉。** KL 是否有新增信息，取决于目标分布是否比 one-hot 标签更丰富。

### 但要警惕“KL”这个词过于宽泛

你必须问：KL 是算在哪里？

```text
A. 候选文档分布上的 KL
   KL(teacher retrieval distribution || student retrieval distribution)

B. token 生成分布上的 KL
   KL(reference LM || current LM)

C. 表示分布或特征分布上的 KL
   KL(teacher representation distribution || student representation distribution)
```

A 与 InfoNCE 最容易重叠；B、C 约束的是不同对象，通常不能简单叫冗余。

### 这里的关键问题

> 如果 KL 的教师只把 one-hot 标签重新说了一遍，它没有新增信息；如果教师提供了相关性的软次序，它就在教 InfoNCE 标签里不存在的东西。

所以判断标准不是“两个 loss 都有 softmax”，而是“第二个 loss 是否增加了独立约束”。

## 第四段 `[肌]`：三个组合，分别判断

### 案例 A：几乎完全冗余

```text
InfoNCE target: [1, 0, 0, 0]
KL target:      [1, 0, 0, 0]
两者作用于：同一批候选、同一组 logits、同一温度
```

此时：

```text
L_total = L_InfoNCE + lambda * L_KL
```

本质上只是把同一个梯度重新加权。它可能改变优化速度，但没有添加新的学习内容。

### 案例 B：互补，但可能冲突

```text
InfoNCE：人工标签说 d1 是正样本
KL：cross-encoder 教师说 d1=0.55, d2=0.40
```

InfoNCE 保住明确监督的排序锚点，KL 让双塔学生吸收教师对 d2 的软判断。二者互补。

但如果教师质量差、领域错位，KL 会把偏差一起蒸馏进来。此时“互补”不是天然好事，而是多引入了一位可能犯错的老师。

### 案例 C：明显不冗余

```text
InfoNCE：训练 query-document 表示空间
KL：约束生成模型不要偏离 reference LM 的 token 分布
```

一个回答“检索谁”，另一个约束“如何生成”。即使都出现 softmax 和 KL，它们作用于不同随机变量，是端到端系统中的不同环节。

**以上三段在支持第三段的论证：是否冗余由监督信息与作用对象决定，而非由公式外形决定。**

## 第五段 `[骨]`：以后看到两个 loss，先问这三问

### 三问判定法

```text
第一问：预测的随机变量相同吗？
        候选文档 / token / 类别 / 表示分布

第二问：目标信号相同吗？
        one-hot 标签 / 软教师分布 / 偏好差值 / 人工分数

第三问：作用粒度相同吗？
        单样本 / batch 内候选 / 全语料近似 / 序列级
```

判断表：

| 情况 | 结论倾向 |
|---|---|
| 三者都相同 | 高度冗余，通常只是重加权 |
| 随机变量相同，目标更丰富 | 可能互补，例如软标签蒸馏 |
| 目标相同，采样或粒度不同 | 可能互补，但要检查梯度冲突 |
| 随机变量不同 | 通常不冗余，是多任务约束 |

### 真正可靠的验证：不要只看总指标

做四组消融：

```text
1. InfoNCE only
2. KL only
3. InfoNCE + KL
4. InfoNCE + shuffled-teacher KL
```

第四组很重要：把教师分布在样本间打乱。如果“InfoNCE + 正确 KL”优于“InfoNCE + 打乱 KL”，说明收益来自教师信息；如果两者差不多，提升可能只是额外正则化、梯度尺度或训练时长造成的。

同时记录：

- Recall@K / nDCG：排序是否更好
- calibration error：概率是否更可信
- 相同训练预算下的收敛速度
- 两个 loss 梯度的 cosine similarity：它们是在同向重复、彼此冲突，还是提供不同方向

```text
cosine 接近 1  ：很可能在重复推动
cosine 接近 0  ：提供近似独立的约束
cosine 小于 0  ：发生冲突，需要权重或采样策略
```

**结构标注：落地判据。** “冗余”最终是一个关于信息增量和梯度增量的可检验命题。

## 旁逸：这与 Margin MSE / DPO 是同一个形状吗？

你昨天指出 Margin MSE 与 DPO 都在学习“相对偏好差值”，这个观察是对的。今天可以再精确一层：

```text
InfoNCE：让正样本在候选集合中的相对概率变大
Margin MSE：让 student 的正负分差逼近 teacher 的分差
DPO：让 chosen 相对 rejected 的隐式奖励差变大，
     同时通过 reference model 保留一个锚
```

三者都不执着于单个对象的绝对分数，而关心对象之间的相对关系；区别在于：

- InfoNCE 的目标通常是“谁赢”的离散标签；
- Margin MSE 的目标是“赢多少”的连续教师差值；
- DPO 的目标是人类偏好对，并以 reference policy 的 log-ratio 作为基准。

它们的“形状”相似，但监督信息量和锚点不同。**同构不等于等价。**

## 今日收束

把答案压成一句可复用的话：

> **InfoNCE 是候选集合上的 one-hot 分布匹配；KL 是通用的分布匹配算子。两者是否冗余，要看 KL 是否只重复同一个 one-hot 目标，还是引入了新的软结构、作用对象或粒度。**

一个实际建议：如果你的 Embedding 模型已有 InfoNCE，又想加 KL，不要先调 lambda；先把下面这张“监督账单”填出来：

```text
InfoNCE 预测对象：________
InfoNCE 目标来源：________
InfoNCE 候选采样：________

KL 预测对象：____________
KL 目标来源：____________
KL 候选采样：____________

KL 新增的信息是：________
```

如果最后一行写不出来，就先假设它冗余。

## 终局问题

当一个软教师分布比 one-hot 标签“信息更多”时，它也同时携带更多教师偏差：**我们该如何区分被蒸馏的是知识，还是教师对线上分布的误解？**

## 术语表

| 英文 | 中文 | 本文含义 |
|---|---|---|
| InfoNCE | 噪声对比估计损失 | 在候选集合中提高正样本相对概率的 softmax 交叉熵 |
| Contrastive learning | 对比学习 | 通过正负关系塑造表示空间 |
| KL divergence | KL 散度 | 衡量目标分布与预测分布差异的分布视角 |
| Soft target | 软目标 | 不只给唯一答案，还保留候选间概率结构 |
| In-batch negatives | 批内负样本 | 把同一 batch 中其他样本用作当前 query 的负例 |
| Temperature | 温度 | 控制 softmax 尖锐程度与梯度集中程度 |
| Knowledge distillation | 知识蒸馏 | 用教师分布训练学生模型 |
| Gradient cosine similarity | 梯度余弦相似度 | 判断两个目标的更新方向是重复、独立还是冲突 |
