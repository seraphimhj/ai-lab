# 数据配比不是预处理，而是隐形的目标函数：用 DoReMi 看懂预训练“给谁更多梯度”

> 本次命中：**retrieval 以外·大模型预训练 + 统一数学框架 + 端到端闭环**；承接昨天“每个 token 该分到多少学习权重”，今天把镜头拉高一层：**在 token 进入模型之前，数据采样比例已经决定了哪些领域能贡献多少梯度。**

## 全局地图

### 一句话摘要

预训练的数据配比 `alpha` 并非 loss 外面的工程细节；它就是领域级的损失权重。DoReMi 的关键不是“多喂困难数据”，而是用**相对参考模型的超额损失**识别“当前模型还没学够”的领域，再把小模型学到的配比迁移给大模型。

### 结构地图

```text
原始语料：web / books / code / papers / wiki / ...
                         |
                         v
                采样比例 alpha_d
                         |
                         v
L(theta) = sum_d alpha_d * E_{x~D_d}[token NLL]
              |
              +-- alpha_d 决定领域 d 获得多少训练步
              +-- 也决定它向参数写入多少梯度
                         |
          人工配比的问题：规模 != 价值 != 未学会程度
                         |
                         v
DoReMi
  1. 用默认配比训练小型 reference model
  2. 训练 proxy model，追逐各领域的 excess loss
  3. 汇总得到领域权重，重采样数据
  4. 用固定新配比训练最终大模型
                         |
                         v
闭环问题：proxy 上的“该补什么”，能否迁移到大模型与下游？
```

## 一、采样比例为什么就是目标函数

### `[骨]` 昨天的 `w_t`，今天多了一个领域权重

标准语言模型预训练通常写成 token 负对数似然：

```text
L(theta) = E_x[-log p_theta(x)]
```

但 `x` 从哪里来？假设语料被分成 `K` 个领域，领域 `d` 的采样概率是 `alpha_d`，那么更完整的写法是：

```text
L(theta, alpha)
  = sum_d alpha_d * E_{x ~ D_d}[-log p_theta(x)]
  = sum_d alpha_d * L_d(theta)
```

这和多任务学习中的加权 loss 是同一个骨架。区别只在实现位置：

```text
显式 loss 加权：样本进来后，把 loss 乘 alpha_d
采样重加权：    让领域 d 以 alpha_d 的概率进入 batch
```

在期望意义上，两者都在控制领域 `d` 对总梯度的贡献：

```text
grad L = sum_d alpha_d * grad L_d
```

所以，数据团队调整“代码占 20% 还是 5%”，不是只在清洗数据；它在改模型真正优化的目标。**数据 mixture 是没有写在模型结构图里的 objective。**

**结构标注：核心论点。** 把“数据配比”接回统一数学框架：token 级有 `w_t`，领域级有 `alpha_d`，两者都在决定谁获得多少参数更新权。

### 碰撞 1

先别往下读，试着判断：

> 一个领域的数据量翻倍，但训练总 token 数不变，模型对该领域的重视程度一定翻倍吗？

不一定。只有采样器按原始 token 比例采样时，原始规模才直接变成训练权重；去重、温度采样、上限截断和人工配比都可能把两者拆开。**“仓库里有多少数据”与“优化器实际看了多少次”是两本账。**

## 二、为什么不能直接给高 loss 领域加权

### `[骨]` 难学，可能只是不可约噪声大

最直觉的策略是：哪个领域 loss 高，就多采哪个。但高 loss 至少混合了三种东西：

```text
observed loss
  = 可学习但尚未学会
  + 领域本身的不可约难度
  + 噪声、错误、随机字符串等数据质量问题
```

例如代码、数学和含大量专名的文本，天然可能比模板化网页更难预测；乱码也会产生很高 loss。若训练器只追逐绝对 loss，它可能把大量预算送给**永远难预测、却未必有价值**的数据。

DoReMi 为此不直接看 proxy model 的 loss，而看它相对 reference model 的**超额损失（excess loss）**：

```text
excess_d(x) = loss_proxy(x) - loss_reference(x)
```

reference model 和 proxy model 规模相近，reference 先按默认 mixture 训练。它像一把“领域难度基线尺”：

- 两个模型在某领域都 loss 很高：它可能只是本来就难；
- reference 已经做得不错，proxy 却落后：proxy 对这里学得不够；
- proxy 已追平或超过 reference：继续抢预算的紧迫性下降。

**结构标注：关键修正。** DoReMi 优化的不是“谁最难”，而是“谁相对合理基线落后最多”。

### 原文锚点

> “The mixture proportions of pretraining data domains ... greatly affect language model performance.”
>
> “预训练各数据领域的混合比例……会显著影响语言模型的表现。”

> “DoReMi ... trains a small proxy model using group distributionally robust optimization over domains to produce domain weights.”
>
> “DoReMi 使用面向各领域的组分布鲁棒优化来训练一个小型代理模型，并由此产生领域权重。”

这里的 `group distributionally robust optimization`（组分布鲁棒优化，Group DRO）不是追求平均领域表现最好，而是让训练动态盯住**相对落后最严重的组**。

## 三、DoReMi 四步到底在做什么

### `[肌]` 第一步：训练 reference model，建立基线

用一组默认领域比例 `alpha_ref` 训练一个较小的 reference model。它不需要完美；它的作用是告诉我们：在这套初始课程下，各领域大致能学到什么程度。

**结构标注：测量基准。** 没有 reference，就无法区分“领域固有难”与“当前训练不足”。

### `[肌]` 第二步：让 proxy model 追逐超额损失最大的领域

训练另一个同等级的小模型 proxy。维护一组随时间变化的领域权重 `q_d`：某领域近期 excess loss 越大，它的权重就提高；proxy 随后从那里获得更多训练信号。

可以把核心博弈写成：

```text
proxy：最小化加权 excess loss
q：    把权重移向 excess loss 更大的领域
```

二者形成 minimax：

```text
min_theta max_q sum_d q_d * E_{x~D_d}[loss_proxy(x) - loss_ref(x)]
```

直觉上，`q` 是一位不断挑短板的考官，proxy 是不断补短板的学生。考官不会永久押注某一科：学生一旦补上，该科的 excess loss 就下降，注意力会移向下一处短板。

**结构标注：方法核心。** 动态权重不是最终目的，它是探针，用来测“有限预算下一 token 最该投到哪里”。

### `[肌]` 第三步：把动态权重汇总成固定 mixture

训练过程中得到一串 `q`，将其平均或汇总，形成最终领域配比。然后按这个配比重采样出新的预训练数据集。

关键点：最终大模型通常不是继续做在线 Group DRO，而是使用小模型发现的**固定配方**。这样把昂贵的 mixture 搜索转移到低成本 proxy 上。

**结构标注：从测量到生产。** proxy 不是缩小版最终产品，而是数据配方搜索器。

### `[肌]` 第四步：用新 mixture 训练 full model

论文实验中，用 280M 参数 proxy 学到的领域权重指导 8B 模型训练；作者报告在 The Pile 上，相比默认配比，平均 few-shot 下游准确率提升 6.5 个百分点，并以约 2.6 倍更少的训练步数达到基线水平。

这些数字说明的是一件比“某个算法涨点”更重要的事：**在模型结构和 token 预算不变时，改变 token 从哪里来，就能改变每一步计算的边际价值。**

**结构标注：经验支持。** 数据分配可以充当算力效率杠杆。

以上四段在支持骨架段“用小模型搜索领域级梯度预算，再迁移给大模型”。

## 四、一个三领域思想实验

### `[肌]` web、code、books 应该怎么分钱

假设默认采样为：

```text
web   70%
code  15%
books 15%
```

训练一段时间后，观察到：

```text
领域    proxy loss    reference loss    excess loss
web       2.4              2.5             -0.1
code      3.8              3.1              0.7
books     3.0              2.9              0.1
```

不要被 `code` 的绝对 loss 最高骗走。真正用于判断的是差值：proxy 在 code 上比 reference 落后最多，因此 `q_code` 上升；web 虽然数据最多，但 proxy 已经追平 reference，边际训练预算可以下降。

一段时间后，code 的 excess loss 被压低，权重又会转移。DoReMi 不是宣布“code 永远更重要”，而是在说：**以当前模型状态和当前基线来看，code 是最没学够的那一组。**

**结构标注：数值直觉。** 动态配比响应的是“相对学习进度”，不是静态领域价值排名。

### 碰撞 2

为什么一个领域被降权后，它自己的 perplexity 反而也可能改善？

一个重要可能性是：默认 mixture 中存在大量重复、低边际价值样本。少看一些该领域，不等于少学有效规律；腾出的预算用于其他领域后，共享表示变好，反过来也帮助这个领域。这里提醒我们：

```text
数据量 != 信息量
采样次数 != 新增梯度信息
领域间也不是彼此独立
```

## 五、把它接回端到端闭环

### `[骨]` 数据偏差不是停留在数据层，它会沿闭环放大

```text
领域划分
   |
   v
采样比例 alpha
   |
   v
梯度暴露量与共享表示
   |
   v
各能力与失败切片
   |
   v
benchmark / reward model 看到的表现
   |
   v
选模、蒸馏、生成新数据
   |
   +-----------------------> 下一轮数据 mixture
```

如果 benchmark 偏重代码，团队就可能提高代码配比；模型代码更强后，又更容易通过代码导向的筛选器生产合成数据，于是原始偏好被一轮轮强化。反过来，一个在线高价值但 benchmark 缺席的领域，即使 DoReMi 内部优化得很漂亮，也可能从一开始就没有被定义为独立 group，信号仍会被平均掉。

这与此前“拒绝过早聚合”的主线完全同构：

```text
检索：单向量过早聚合 -> 实体信号消失
评测：单均值过早聚合 -> 失败切片消失
预训练：粗领域过早聚合 -> 稀缺能力的学习缺口消失
```

**旁逸：这里和 mixture-of-experts 是同一个形状。**

- MoE 的 router 决定：这个 token 把计算预算送给哪个专家；
- 数据 mixture 决定：这个训练步把梯度预算送给哪个领域。

一个分配模型内部计算容量，一个分配模型外部学习机会。二者的共同难题都是：**若只按当前强信号路由，强者会更强，弱者会因得不到训练而永久变弱。** 所以 MoE 需要负载均衡，数据 mixture 需要防止领域权重坍缩。

**结构标注：闭环提升。** 配比不是一次性超参，而是评测偏好、数据生产和下一轮训练之间的反馈接口。

## 六、最强反驳：proxy 学到的配比凭什么适合大模型

### `[骨]` DoReMi 的成功依赖一个未被公式保证的迁移假设

压力测试如下：

> 280M 模型觉得某类数据“最缺”，8B 模型也一定最缺吗？

未必。模型规模变化可能改变：

- 各领域的 scaling rate；
- 能否从跨领域数据中迁移；
- 对噪声和长尾模式的拟合能力；
- 训练早期与后期最有价值的数据类型。

因此，DoReMi 真正押注的是一种**排序稳定性**：小模型测出的“哪些领域边际价值更高”，在大模型上大体仍成立。论文结果给了经验支持，但它不是普遍定理。

此外还有三层边界：

1. **领域划分边界**：group 定义得太粗，少数能力仍会被组内平均；定义得太细，估计噪声增大。
2. **reference 边界**：reference mixture 带着人的先验；excess loss 衡量的是“相对这把尺落后”，不是绝对社会价值。
3. **目标边界**：不使用下游任务可以避免对某个 benchmark 过拟合，但也意味着它无法知道线上哪类错误代价最高。

**结构标注：最强反驳。** DoReMi 优化的是“给定分组、给定 reference、给定 proxy 可迁移性”下的稳健配比，不是自动发现世界上最有价值的数据。

**如果训练早期需要广覆盖、后期需要补能力短板，那么“一个固定 mixture 训到底”会不会像“一个固定学习率训到底”一样粗糙？进一步说，课程学习、在线评测与数据采样器能否组成稳定闭环，而不把短期评测偏好无限放大？**
