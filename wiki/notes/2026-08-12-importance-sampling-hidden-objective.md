# 采样不是搬运数据：Importance Sampling 如何统一 DoReMi、难负例与离线评估

*本次命中：「统一数学框架」与「数据 -> 采样 -> 目标函数 -> 评测 -> 线上分布」端到端闭环薄弱点；把最近的 DoReMi、难负例和 IPS 三块拼成同一张图。*

## 一句话摘要

训练或评测时，一旦样本来自分布 `q`，而你真正关心的是分布 `p`，不加修正的平均值就在回答 `q` 的问题；importance weight `p(x)/q(x)` 能把问题改回 `p`，但会以方差为代价，因此采样、加权与裁剪共同定义了模型真正优化的目标。

## 全局地图

Agent 判断：

- `[骨]` “从哪里采样”和“每个样本算多重”不是数据管道细节，而是目标函数本身。
- `[肌]` 期望可以改写为 `E_p[f] = E_q[(p/q)f]`，前提是目标分布会出现的地方，采样分布也必须覆盖。
- `[骨]` DoReMi、难负例、IPS 看似分属预训练、检索和 Agent 评测，其实都在处理 `p` 与 `q` 的错位。
- `[肌]` importance weighting 的代价是高方差；裁剪、归一化和混合采样都是在偏差与方差之间交易。
- `[骨]` 闭环设计的关键问题不是“数据够不够多”，而是“我们正在估计哪个分布下的什么量”。

```text
真实关心的分布 p
        |
        |  直接采样太贵 / 看不到反事实 / 梯度太弱
        v
实际采样分布 q -----> 收集到的样本
        |                    |
        |                    v
        +-------------> 权重 w = p/q
                             |
                             v
                    加权训练或加权评测
                             |
                  +----------+----------+
                  |                     |
                  v                     v
             目标偏差变小           方差可能变大
                  |                     |
                  +----------+----------+
                             v
                    裁剪 / 混合 / 重采样
```

最值得带走的一句是：

```text
采样决定你看见谁，权重决定你听谁的。
```

## 第一段 `[骨]`：经验平均并不天然代表“真实世界”

假设我们关心某个目标分布 `p(x)` 下的平均损失：

```text
R_p(theta) = E_{x~p}[ L(theta; x) ]
```

这里的 `p` 可能是线上请求分布、希望服务的人群分布，也可能是我们人为规定的“各领域同等重要”的评测分布。

但实际数据常来自另一个分布 `q(x)`：日志由旧策略收集，预训练语料按网页存量出现，难负例被检索器刻意挑选。若直接求普通平均，优化的其实是：

```text
R_q(theta) = E_{x~q}[ L(theta; x) ]
```

`R_p` 和 `R_q` 形式完全相同，只差下标，因此这个错位很容易被藏起来。可一旦 `p != q`，它们就是两个不同问题。

比如，某类线上失败只占训练样本很小一部分。即使模型在这类样本上损失极高，普通平均仍可能被大量容易样本淹没。模型没有“忽视异常”，它只是忠实地优化了你用 `q` 定义出来的目标。

*结构标注：核心论点。经验平均回答的是采样分布的问题，而不是自动回答真实世界的问题。*

回想最近三篇伴读：DoReMi 改变领域配比，难负例挖掘改变候选组成，IPS 修正旧策略日志。它们都动了数据，但分别是在“制造一个更好的 `q`”，还是“从 `q` 恢复 `p`”？先留下判断，后文会把它们逐一归位。

## 第二段 `[肌]`：那条看似神奇的换分布公式

只要满足一个关键条件：凡是 `p(x) > 0` 的地方，都有 `q(x) > 0`，就可以写：

```text
E_{x~p}[f(x)]

= sum_x p(x) f(x)

= sum_x q(x) [p(x)/q(x)] f(x)

= E_{x~q}[ w(x) f(x) ]
```

其中：

```text
w(x) = p(x) / q(x)
```

这就是重要性加权（importance weighting）；若强调“从一个分布采样、估计另一个分布的期望”，通常称为重要性采样（importance sampling）。

它没有凭空创造信息，只是重算话语权：

- `p(x) > q(x)`：目标世界比采样数据更常见，权重大于 1，要放大；
- `p(x) < q(x)`：采样数据中过度出现，权重小于 1，要压低；
- `q(x) = 0` 且 `p(x) > 0`：样本从未出现，分母为零，任何加权都救不回来。

最后一条叫覆盖或支持集条件（support condition）。它是整套方法最硬的边界：*重加权能纠正“比例错了”，不能纠正“完全没看见”。*

*结构标注：数学骨架。用密度比 `p/q` 把 `q` 下的观测改写成 `p` 下的期望。*

## 第三段 `[骨]`：DoReMi——不是恢复自然分布，而是在设计一个值得优化的分布

DoReMi 处理的是预训练领域配比。原始网页语料的占比可记为自然分布 `q_raw(domain)`，但网页里什么多，不等于产品希望模型最擅长什么。代码、数学、百科、论坛的“库存量”不是价值函数。

DoReMi 学到一组领域权重，然后重采样或加权训练。这里容易产生一个误解：它不一定是在恢复某个客观存在的“真实分布”。很多时候，目标分布 `p_target` 本身就是设计选择：我们希望哪些领域得到更多梯度。

```text
原始语料库存 q_raw
        |
        |  领域权重 / 重采样
        v
训练目标分布 p_target
        |
        v
模型容量被分配到哪些领域
```

因此 `p` 并不总是自然真相。它可能是一份产品契约、一组公平性要求，或一个 minimax 目标。统一公式没有替你决定价值，只迫使你把价值选择写出来。

*结构标注：第一处映射。DoReMi 通过改变领域的有效权重，把“数据配比”显式变成训练目标。*

### 碰撞：最强反对意见

有人会说：“既然可以加权，那何必重采样？保留所有数据，在 loss 上乘权重即可。”

数学期望上，两者可以指向同一目标；优化过程却不一定等价。极低概率领域即使权重大，如果一个 batch 根本采不到，便没有梯度；极大权重还可能让少量样本主导更新。重采样控制“多久看到一次”，加权控制“看到后听多大声”，两者影响梯度方差、batch 组成和训练稳定性。

## 第四段 `[骨]`：难负例——它更像主动设计 `q`，而不是恢复 `p`

昨天的难负例伴读说：随机负例常离决策边界太远，softmax 概率接近零，几乎不给梯度。难负例挖掘于是故意把采样分布从“语料库里随机抽”改成“当前模型最容易混淆的候选”。

```text
随机负例分布 q_random
        |
        |  hard-negative miner
        v
边界附近分布 q_hard
        |
        v
更多梯度集中在细粒度错误上
```

这里的目的通常不是让训练集忠实模拟线上文档总体分布，而是提高有限训练预算的信息密度。也就是说，难负例采样常在主动制造一个偏置的 `q_hard`。

这不代表应该机械地乘上 `p_online/q_hard` 把它改回去。若那样做，可能又把最需要的边界信号压低。首先要问清目标：

1. 若目标是无偏估计线上平均风险，就需要考虑分布修正；
2. 若目标是塑造某条决策边界，偏置采样本来就是训练策略；
3. 若还把 hard-mined batch 的普通平均叫作“线上风险”，才发生了概念偷换。

假负例之所以危险，也能用这套语言重述：miner 让某些高相似候选在 `q_hard` 中过度出现，它们又在 softmax 中获得大梯度；一旦标签错，*采样概率与梯度权重同时放大错误*。

*结构标注：第二处映射。难负例不是被动纠偏，而是主动改变采样分布，把算力集中到决策边界。*

### 旁逸：主动学习是同一个形状

主动学习不随机标注所有样本，而优先选择模型最不确定的点。难负例挖掘也不是平均观察世界，而是让模型盯住自己的边界。二者共同的风险是：选择器由当前模型驱动，模型看不见的盲区可能永远不会被选中。

```text
当前模型 -> 选择“最有价值”的样本 -> 新数据 -> 更新模型
    ^                                      |
    +--------------------------------------+
```

这是闭环，不是独立同分布的数据管道。

## 第五段 `[骨]`：IPS——这一次确实是在用 `q` 的日志回答 `p` 的问题

离线评估 Agent 或推荐策略时，我们想知道新策略 `pi` 的效果，却只有旧策略 `mu` 产生的日志。动作 `a` 是按 `mu(a|x)` 选择的，因此观测分布是 `q = mu`；目标却是新策略下的 `p = pi`。

逆倾向评分（Inverse Propensity Scoring, IPS）写成：

```text
V(pi)

= E_{x, a~pi}[ r(x,a) ]

= E_{x, a~mu}[ pi(a|x) / mu(a|x) * r(x,a) ]
```

这里的权重：

```text
w(x,a) = pi(a|x) / mu(a|x)
```

含义很直白：某动作若新策略比旧策略更常选，就提高这条日志的代表性；反之则降低。

这与难负例的关键区别在于任务语义：

```text
难负例: 我故意改变 q，想获得更有用的训练梯度
IPS:    我被迫只有 q 的数据，想估计 p 下的新策略价值
```

IPS 的覆盖条件也极其具体：如果新策略会选择某动作，而旧策略从未选择它，那么日志里没有该动作的奖励。`pi/mu` 的分母为零，离线数据无法回答这个反事实。模型再强、公式再漂亮，也不能从“从未行动”推断“行动后的真实结果”。

*结构标注：第三处映射。IPS 是标准的分布恢复问题：从旧策略日志估计新策略的期望奖励。*

## 第六段 `[肌]`：无偏为什么仍可能不好用——权重把稀有样本变成“单点否决”

假设某动作在旧策略下极少出现、在新策略下却很常见，则 `pi/mu` 会非常大。一条偶然日志就可能压过其余样本。重复采集很多次，估计量在平均意义上可以正确；但你手里这一份有限数据，结果可能剧烈摇摆。

这就是 importance sampling 的核心代价：

```text
分布错位越大
    -> 密度比 p/q 越极端
    -> 少量样本权重越大
    -> 估计方差越高
    -> 有效样本量越低
```

“日志有一百万条”不等于“对新策略有一百万条信息”。若绝大多数权重接近零，真正支撑结论的可能只是很少几条。

常见修法都在偏差与方差之间做交易：

1. *权重裁剪*：使用 `min(w, c)`，阻止极端权重支配结果；方差下降，但引入偏差。
2. *自归一化*：用 `w_i / sum_j w_j` 做加权平均；有限样本更稳定，但不再严格无偏。
3. *混合策略收集*：让旧策略保留一定探索概率，改善覆盖；这是从数据源头降低未来权重爆炸。
4. *Doubly Robust*：把奖励模型的预测与 IPS 修正结合；模型正确或 propensity 正确，满足其一仍可能得到可靠估计。
5. *限制策略更新幅度*：不让新策略离日志策略太远，从而控制密度比；这与 RL 中 trust region / KL 约束是同一种稳定思想。

*结构标注：代价与修法。无偏性不是免费午餐，分布修正会把偏差问题转换成方差问题。*

以上两段共同支持：IPS 的难点不在记住公式，而在覆盖、权重尾部与有限样本可靠性。

## 第七段 `[骨]`：统一框架——先分清“改问题”还是“答原问题”

现在把三类方法放进同一张表：

```text
方法          实际采样 q                 想要的 p / 目标             主要动作

DoReMi        原始领域混合               设计出的领域目标           改 q 或加权，重分容量
难负例        随机或当前候选分布         决策边界附近的训练信号     主动改 q，提高梯度密度
IPS           旧策略日志 mu              新策略 pi 的期望回报       用 p/q 恢复目标期望
```

真正该先问的不是“要不要 importance weighting”，而是下面三个问题：

```text
1. Estimand: 我究竟想估计或优化什么量？
2. Sampling: 数据实际上由什么机制产生？
3. Correction: 我是要保留采样偏置，还是把它纠正回目标分布？
```

这里的 estimand 可译为“目标量”：你最终声称自己测到的那个东西。例如“旧日志覆盖范围内的新策略平均奖励”，和“新策略在线部署后的总体平均奖励”不是同一个目标量。

如果这三问没有写清，常见错误会成对出现：

- 训练时：以为采样只是提速，没意识到它改了梯度目标；
- 评测时：把日志上的普通平均误称为新策略价值；
- 纠偏时：只追求无偏，却忽视权重爆炸让结论不可用；
- 产品时：把人为设计的目标分布包装成“自然真实分布”。

*结构标注：统一结论。采样与加权的意义取决于目标量；同一公式既能恢复问题，也能重新定义问题。*

## 一个可直接使用的诊断模板

以后遇到数据配比、重采样、hard mining、离线策略评估或 domain adaptation，可以先填这六行：

```text
目标量:
目标分布 p:
观测 / 采样分布 q:
覆盖条件是否成立:
是否需要权重 p/q:
若裁剪权重，愿意接受什么偏差来换多少稳定性:
```

再做一项闭环检查：

```text
当前模型是否参与产生 q？

否 -> 主要是静态分布错位
是 -> 模型 -> 采样 -> 新数据 -> 模型，需检查选择偏差会不会自我强化
```

难负例挖掘、推荐日志、Agent 自主探索都属于后者。

## 压力测试

有人提出一个看似合理的统一方案：

> 所有非随机采样都乘 `p/q`，这样既能高效采样，又能保持无偏。

这个说法只在“目标始终是 `p` 下的期望”时成立。如果我们故意 oversample 安全事故、稀有语言或细粒度实体错误，是为了让模型比自然频率更重视它们，那么目标本来就已从自然分布风险改成了风险敏感目标。此时把权重完全除回去，会取消设计意图。

所以最强回应不是讨论公式，而是追问：

> 你说的 `p` 是线上自然频率，还是产品真正愿意承担的代价分布？

频率与代价不是一回事。罕见但灾难性的错误，即使在 `p_online` 下概率低，也可能在业务目标中拥有高权重。

## 全文复盘

### 理解轨迹

```text
普通平均
  -> 只代表采样分布 q
  -> 用 p/q 可恢复目标分布 p
  -> 但覆盖缺失无法补救
  -> 权重极端会放大方差
  -> 裁剪用偏差换稳定
  -> 更根本地，p 本身可能是价值选择
```

三篇旧内容现在落在同一个框架里：

```text
DoReMi:      设计“谁更值得被训练”
难负例:     设计“哪条边界更值得花梯度”
IPS:        纠正“日志看见谁”与“新策略会做谁”的错位
```

### 读后一句话（不可跳过）

读完后，请给作者一句判断，不要只复述公式：

> *在我的一个真实训练或评测流程里，我以为自己在优化 `p`，但数据其实来自 ______ 的 `q`；这个错位应当保留，还是修正？为什么？*

### 终局问题

如果线上分布 `p_online` 本身由模型行为塑造——推荐模型决定用户看见什么，Agent 决定探索哪些工具路径，检索器决定哪些文档获得点击——那么“恢复真实分布”究竟是在恢复一个外部世界，还是在恢复模型自己制造出来的世界？
