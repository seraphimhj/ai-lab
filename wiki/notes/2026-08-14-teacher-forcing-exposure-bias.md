# Teacher Forcing 的隐形裂缝：训练时总看正确历史，上线后却活在自己的历史里

> 命中薄弱点：**端到端闭环 + 统一数学框架 + Agent / 上下文工程**。今天补的是“训练目标如何改变上线时会遇到的数据分布”：模型的输出一旦回流成下一步输入，误差就不再只是一次预测错，而会改写后续问题本身。

## 全局地图

### 一句话摘要

Teacher forcing 用正确前缀高效学习每个 token 的条件概率，本身就是标准最大似然；真正的裂缝在于，有限模型上线后会进入由自己错误诱发、训练时很少见过的前缀，而修复它不能只靠“把自己的输出掺进训练”，必须同时回答三个问题：去哪里采状态、谁给这些状态正确动作、最终按 token 还是按整条轨迹评价。

### 结构地图

```text
训练：数据前缀 y*_<t
          |
          v
   p_theta(y_t | x, y*_<t)
          |
          | 每一步都站在正确历史上
          v
       token NLL

上线：模型前缀 yhat_<t
          |
          v
   p_theta(y_t | x, yhat_<t)
          |
          | 一次错误改变下一步输入
          v
  新状态 -> 新错误 -> 更远的新状态

裂缝不是一句“train-test mismatch”就结束：

  状态分布错位  -> 在模型会到达的状态上收数据
  监督信号错位  -> 为这些状态补正确动作/恢复动作
  评价粒度错位  -> 用序列级任务结果约束 token 更新
```

### 段落分类（Agent 判断）

- `[骨]` Teacher forcing 到底优化了什么

## 一、[骨] Teacher forcing 不是作弊，而是最大似然的自然分解

给定输入 `x` 和目标序列：

```text
y* = (y*_1, y*_2, ..., y*_T)
```

自回归模型把整条序列的概率分解为：

```text
p_theta(y* | x)
= product_t p_theta(y*_t | x, y*_<t)
```

取负对数后：

```text
L_MLE(theta)
= - sum_t log p_theta(y*_t | x, y*_<t)
```

训练第 `t` 个位置时，把真实历史 `y*_<t` 喂给模型，这就是 **teacher forcing（教师强制）**。它不是额外加上的小技巧，而是对数据序列做最大似然估计时最直接的实现。

它有一个巨大的计算优势：目标序列的所有正确 token 已知，Transformer 可以通过 causal mask 一次并行计算所有位置的 loss。若训练时必须先生成第 1 个 token，再把采样结果喂回第 2 步，就会把训练也变成难以并行的自回归循环。

所以先把一个常见误解钉住：

```text
teacher forcing = 错误目标       X
teacher forcing = 序列 MLE 的标准训练方式  √
```

问题不是“训练时为什么给答案”，而是：**模型只在数据产生的前缀上接受纠正；部署时，它却可能走进自己产生的前缀。**

**结构标注：核心定义。** 先把 teacher forcing 与最大似然对齐，避免把后面的分布错位误诊成“训练作弊”。

### 碰撞问题

如果模型已经精确学到了真实数据分布的所有条件概率，teacher forcing 还会必然造成 exposure bias 吗？

不会。若模型完美、数据无限、模型族正确，那么从模型采样得到的前缀分布就与数据分布一致，裂缝消失。所谓 exposure bias 依赖于现实条件：有限数据、有限容量、优化误差、错误解码或任务本身多解。它不是 MLE 在逻辑上必然错误，而是**局部误差进入闭环后造成的分布偏移**。

## 二、[肌] 单步 98% 正确，不等于 50 步任务有 98% 成功率

先看一个刻意简化的心算模型：假设每一步都必须正确、每步正确率固定为 `p`、错误彼此独立，那么长度为 `T` 的整条轨迹全对概率是：

```text
P(all correct) = p^T
```

当 `p = 0.98`：

```text
20 步全对：0.98^20 约为 0.668
50 步全对：0.98^50 约为 0.364
100 步全对：0.98^100 约为 0.133
```

这不是语言模型真实成功率公式：真实错误并不独立，有些错误可恢复，有些任务容许多种正确序列。但它揭示了第一层风险：**序列成功通常是多个局部决策的联合事件。**

更麻烦的是第二层：实际闭环中，错误往往相关。假设正确轨迹是：

```text
用户：把会议改到周五，并通知参会人

正确动作：
1. 查找原会议
2. 修改日期
3. 获取参会人
4. 发送变更通知
```

若 Agent 在第 1 步查错了会议，后续三步即使“相对于当前上下文都很合理”，整条任务仍在错误对象上越走越远。第 1 步不是只贡献一个错误；它**生成了一个新的状态分布**。

```text
查错会议
   |
   v
错误 meeting_id 进入上下文
   |
   +--> 修改错对象
   +--> 读取错名单
   +--> 向错的人发送通知
```

以上数值例子支持第一节：闭环任务不能从单步准确率直接推出整条轨迹可靠性。

**结构标注：误差放大例。** 从独立乘法风险推进到更真实的“错误改变后续状态”。

## 三、[骨] Exposure bias 的本质：策略决定自己未来会看到什么

首次出现的术语：**exposure bias（暴露偏差）**，指训练时主要暴露在真实前缀，推理时却暴露在模型自身生成前缀，因而产生的状态分布差异。

把它写成两个分布：

```text
训练前缀：s_t = (x, y*_<t)     ~ d_data
上线前缀：s_t = (x, yhat_<t)   ~ d_pi
```

其中 `d_pi` 不是一个外部固定测试集。它由模型策略 `pi` 自己产生：模型改变一个动作，就改变接下来会访问哪些状态。

这使序列建模与普通 i.i.d. 分类出现根本差异：

```text
普通分类：
预测错一张猫图，不会改变下一张测试图。

自回归生成/Agent：
预测错一个 token 或工具参数，会改变下一步模型看到的上下文。
```

因此，真正的闭环是：

```text
参数 theta
   |
   v
策略 pi_theta
   |
   v
访问状态分布 d_pi
   |
   v
这些状态上的预测难度与错误
   |
   +--------------------> 反过来决定后续 d_pi
```

这正好接上我们前几天讨论的 importance sampling：那里问“数据从哪个分布采，目标却想对哪个分布求期望”；这里更进一步——**目标分布不是静止的，它随正在训练的策略一起移动。**

标准 teacher forcing 优化的是：

```text
E_{s ~ d_data} [ loss(pi_theta(s), expert_action) ]
```

部署真正关心的更像：

```text
E_{s ~ d_pi} [ task_cost(pi_theta(s)) ]
```

两者不只 loss 不同，连采样状态的分布都不同。

**结构标注：全文主轴。** Exposure bias 不是一句“训练和推理不一致”，而是策略诱导的 covariate shift（协变量漂移）。

### 注疏：一条侧光

这里与因果推断中的 intervention（干预）同构：你不能只在专家策略产生的世界里学习模型策略会怎样行动，因为一旦把模型部署进去，模型的动作会干预世界，进而改变后续观测。离线日志描述的是“旧策略造成的世界”，不是“新策略上线后的世界”。

### 压力测试

有人说：“只要训练集足够大，包含各种错误前缀，问题自然解决。”最强的反问是：

> 哪些错误前缀值得包含，由谁决定？

可能前缀呈指数增长，均匀覆盖不可能。有效数据必须集中在**当前策略真实容易到达、且失败代价高的状态**。所以问题从“数据够不够多”变成“采样策略是否跟着模型更新”。

## 四、[骨] Scheduled sampling：看见了分布错位，却不一定给出了正确监督

Bengio 等人在 2015 年提出 **scheduled sampling（计划采样）**。核心做法是：训练早期多使用真实前缀，随后逐渐以更高概率把模型自己的预测作为下一步输入。

```text
训练第 t 步的前缀来源：

以概率 epsilon：使用真实 token y*_(t-1)
以概率 1-epsilon：使用模型 token yhat_(t-1)

随训练推进，epsilon 逐渐减小
```

直觉非常诱人：既然上线会看见自己的错误，那就让模型训练时提前见一见。

但这里藏着一个监督错位。假设真实句子是：

```text
The cat sat on the mat.
```

模型前一步误生成：

```text
The dog ...
```

scheduled sampling 仍可能要求下一步预测原参考句同位置的：

```text
cat 之后的目标：sat
```

`The dog sat ...` 也许尚可；但若模型生成的是 `The weather ...`，仍强迫同位置输出 `sat`，目标就未必是当前前缀下合理的“专家动作”。它把两个问题混在了一起：

1. 应不应该访问模型产生的状态？——应该；
2. 到达这个状态后，原序列同位置 token 还是不是正确监督？——不一定。

Huszár 在 2015 年对 scheduled sampling 的批评正打在这里：这种混合目标并非 proper scoring rule（严格意义下的恰当评分规则），即便数据和容量无限，也不保证真实序列分布是目标的最优解；模型甚至可能通过忽略前缀依赖来降低冲突。

所以不能把修法简化成：

```text
train-test mismatch
      |
      v
训练时掺入模型输出
      |
      v
问题解决
```

更完整的是：

```text
在模型状态上训练
      +
为该状态定义有效目标
      +
让训练目标与部署指标一致
```

**结构标注：关键反例。** Scheduled sampling 修了“去哪里采样”，却可能没有修好“在那里教什么”。

## 五、[骨] DAgger 给出的不是一个技巧，而是三问框架

模仿学习中的 **DAgger（Dataset Aggregation，数据集聚合）** 提供了一个更干净的思路。它不是只把模型动作塞回输入，而是反复执行：

```text
1. 用当前策略 pi_i 实际跑任务
2. 收集它真正访问到的状态 s ~ d_pi_i
3. 请专家为这些状态标注正确动作 a*
4. 把新状态-动作对聚合进数据集
5. 训练新策略 pi_(i+1)
```

ASCII 图：

```text
专家轨迹数据 D_0
      |
      v
训练 pi_1
      |
      v
pi_1 跑出自己的状态 --------+
      |                       |
      v                       |
专家标注这些状态的正确动作    |
      |                       |
      v                       |
D_1 = D_0 + 新数据            |
      |                       |
      v                       |
训练 pi_2 --------------------+
```

真正值得带走的是三个彼此独立的问题：

### 1. State distribution：在哪里训练？

不是只在专家会到达的完美状态，也要在当前模型实际上会到达的偏离状态。

### 2. Oracle：偏离后谁知道正确动作？

原参考轨迹未必仍有效。需要人类、规则引擎、环境状态、可执行验证器，或能从当前状态重新规划的强教师。

### 3. Objective：什么算成功？

逐步模仿专家动作未必等于完成任务。任务可能存在多条正确路径，因此还要看最终状态、约束是否满足、是否产生不可逆副作用。

这三问把许多看似不同的方法排到同一张表里：

| 方法 | 状态从哪来 | 监督/奖励从哪来 | 优化粒度 |
|---|---|---|---|
| Teacher forcing | 数据/专家前缀 | 下一个真实 token | token |
| Scheduled sampling | 数据与模型混合前缀 | 原序列同位置 token | token |
| DAgger | 当前策略访问的状态 | 专家在该状态重新标注 | action/state |
| Sequence RL | 当前策略采样序列 | 整体 reward / verifier | sequence/trajectory |
| Agent 在线纠错数据 | 真实或回放轨迹 | 工具结果、人类修正、验证器 | step + task |

**结构标注：统一框架。** 修 exposure bias 的方法，可以按“状态、教师、目标粒度”三轴定位，而不是逐个背名称。

### 你可以停十秒

如果只有模型生成轨迹，却没有“偏离后该怎么恢复”的可靠标注，增加 rollout 数据会发生什么？

它可能只是让模型更熟悉自己的错误，甚至把失败轨迹再蒸馏回自己。**on-policy 数据不是自动正确的数据。** “来自当前策略”只解决分布覆盖，不解决标签质量。

## 六、[肌] 同一病灶在语言模型、RAG 和 Agent 中如何复现

### A. 语言模型：错误 token 改写语义空间

```text
错 token
  -> 后续条件概率改变
  -> 生成进入不同主题/句法分支
  -> 原参考 continuation 不再唯一合理
```

对应修法包括：更好的数据覆盖、序列级偏好优化、可验证任务上的 outcome reward、搜索与重排序，以及专门的纠错轨迹。重点不是取消 MLE，而是补足 MLE 在模型诱导状态上的盲区。

### B. RAG：一次错检索污染后续查询

Agentic RAG 中，第一轮召回结果常被用来改写第二轮 query：

```text
错误召回
  -> 生成错误中间结论
  -> 用错误结论扩展 query
  -> 第二轮检索更偏
  -> “证据”看似越来越一致
```

这里的 exposure 不再只是 token 前缀，而是**检索轨迹产生的证据状态**。只在“黄金文档已给定”的数据上训练 reader，会高估真实 RAG 能力；评测必须把系统放进自己召回的上下文。

### C. Agent：工具副作用会把错误写进外部世界

```text
语言模型：错误主要留在上下文
RAG：错误进入证据池
Agent：错误可能写入数据库、日历、代码仓库或消息系统
```

Agent 的恢复尤其难，因为状态可能不可逆。训练“下一步工具调用”还不够，系统需要：

- 可回滚动作优先；
- 写操作前验证；
- 从真实 tool error 与脏状态恢复的轨迹；
- 把“未验证观察”和“确认事实”分栏；
- 用最终环境状态而非自然语言自评判定成功。

以上三组例子支持第五节：状态不只有 token，凡是由模型动作产生并回流为输入的东西，都会形成 exposure bias 的广义版本。

**结构标注：跨域迁移。** 把序列模型的前缀漂移推广到检索证据与外部环境状态。

## 七、[骨] 工程上别只测“在正确前缀上会不会”，还要测“偏离后回不回得来”

传统 token NLL 或 teacher-forced accuracy 回答的是：

> 给你一段正确历史，下一个 token 预测得怎么样？

闭环系统还需回答：

> 给你一段带有真实错误、缺失观察或工具异常的历史，你能否识别偏离、停止扩散并恢复？

可以把评测拆成四层：

```text
1. Clean-prefix quality
   正确前缀下的 NLL / accuracy

2. Perturbed-prefix robustness
   人工插入错 token、错实体、缺证据后，性能下降多少

3. Recovery rate
   已偏离后，能否在 k 步内回到可成功状态

4. End-state correctness
   最终数据库/文件/任务状态是否满足约束
```

一个实用的 Agent 测试不应只有“从头独立跑 100 次”，还应包含**中途注入故障**：

```text
- 工具返回空结果
- 检索首条是高相似度假证据
- 上一步摘要混入一个错误实体
- API 写入成功但响应超时
- 用户约束在长上下文中被压缩遗漏
```

然后测三件事：是否察觉、是否阻断副作用、是否恢复。

这会改变训练数据的采集方式。最有价值的数据不一定是更多完美示范，而可能是：

```text
失败状态
  + 正确诊断
  + 最小回滚动作
  + 恢复后的成功轨迹
```

它相当于为模型补上“专家从不会到达、模型却经常到达”的地图。

**结构标注：工程结论。** 从干净前缀的平均能力，转向策略诱导状态上的恢复能力与最终状态正确性。

## 一页纸复盘

### 统一公式

```text
Teacher forcing：
min E_{s ~ d_data} [token_loss]

部署闭环：
状态 s_t 由历史模型动作产生
因此 s_t ~ d_pi，而 d_pi 随策略改变

真正要补的三件事：
1. 在 d_pi 上采到状态
2. 为这些状态得到有效监督/奖励
3. 按真实任务粒度评价结果
```

### 四句带走

1. Teacher forcing 不是旁门技巧，而是自回归最大似然的标准实现。
2. Exposure bias 的核心不是“见过自己的输出”这么简单，而是策略改变了未来输入分布。
3. Scheduled sampling 只把模型前缀混进来，未必能为偏离状态提供一致的正确目标。
4. 对 Agent，最稀缺的数据往往不是完美成功轨迹，而是“偏离后如何识别、回滚并恢复”的轨迹。

## 理解轨迹

```text
“训练给正确前缀，所以推理有 mismatch”
                  |
                  v
“局部误差会改变下一步状态分布”
                  |
                  v
“修复需要模型状态上的新监督”
                  |
                  v
“状态覆盖、教师质量、任务目标必须分开看”
                  |
                  v
“闭环系统的核心指标之一是恢复能力”
```

## 读后一句话（不可跳过）

读完后，请只对这篇伴读说一句话：**在你正在做的系统里，模型一次输出会通过哪条路径变成它下一步的输入？那条路径上最缺的是状态覆盖、正确监督，还是最终结果验证？**

## 终局问题

如果“恢复能力”只在模型犯错后才可观察，那么我们怎样采集足够多的失败状态来训练恢复，又不让真实用户承担探索这些失败的代价？离线扰动、沙箱 rollout、规则验证器与人类接管之间，边界应该怎样分配？

## 下一步线索

下一步只追两处，不展开成书单：

1. Samy Bengio 等，*Scheduled Sampling for Sequence Prediction with Recurrent Neural Networks*（2015，arXiv:1506.03099）：重点看它如何用退火概率混合真实 token 与模型 token。
2. Stéphane Ross、Geoffrey Gordon、Drew Bagnell，*A Reduction of Imitation Learning and Structured Prediction to No-Regret Online Learning*（AISTATS 2011）：重点看 DAgger 为什么必须让专家标注“学习者实际访问到的状态”。

阅读时带着一个校验问题：**方法只是让训练输入更像部署输入，还是也保证了偏离状态上的监督仍然正确？**
