# GRPO 的长度偏置：一句奖励，为什么会在 token 级更新里悄悄改写目标？

> 本次命中：**统一数学框架 + 端到端闭环 + 后训练**。递进 08-18 的 GAE 与 08-19 的组内基线：今天不再问“优势从哪来”，而问“同一个序列优势怎样分摊给 token，以及这个分母到底在优化什么”。

## 全局地图

### 一句话摘要

GRPO 虽然只给整条回答一个奖励，却必须通过 token 级 log-probability 更新策略；此时“先对每条回答按长度平均，再对组平均”和“把全组所有 token 一起平均”不是实现细节，而是两个不同目标，前者可能让短回答获得更大的梯度话语权。

### 结构地图

```text
题目 x
  |
  +-- 采样 G 条回答 y_1 ... y_G
  |      |
  |      +-- 每条得到序列奖励 r_i
  |
  +-- 组内标准化 -> 优势 A_i
  |      |
  |      +-- 同一 A_i 广播给回答 i 的每个 token
  |
  +-- token 级 PPO/GRPO surrogate
         |
         +-- 先按序列平均 -> 每条回答权重相同 -> 短回答每 token 更重
         |
         +-- 按所有 token 平均 -> 每个 token 权重相同 -> 长回答总权重更大
```

## 1. `[筋]` 接上昨天：组内基线只解决“相对谁好”

昨天的核心是：GRPO 不训练一个 Critic，而是在同一道题的多条回答中，用组均值作为基线：

```text
A_i = (r_i - mean(r_1 ... r_G)) / std(r_1 ... r_G)
```

它回答的是：*回答 i 相对同组其他回答好多少？*

但它没有回答另一个问题：一条回答有 20 个 token，另一条有 200 个 token，同一个序列优势 `A_i` 应该怎样分给这些 token？

**结构标注：** 作者从“优势的参照系”过渡到“优势的分配单位”。

## 2. `[骨]` 从序列奖励到 token 梯度

### 原始骨架（English / 中文并列）

> *A sequence-level reward must be converted into token-level policy updates.*  
> 序列级奖励必须被转换成 token 级策略更新。

一条回答写作 `y_i = (y_i,1, ..., y_i,T_i)`。验证器通常只在整条回答结束后给一个奖励 `r_i`，组内标准化后得到一个优势 `A_i`。GRPO 随后把同一个 `A_i` 广播给这条回答的每个 token：

```text
L_i = average over t in 1...T_i of
      min(
        ratio_i,t * A_i,
        clip(ratio_i,t, 1-eps, 1+eps) * A_i
      )
```

其中：

- `ratio_i,t = pi_theta(y_i,t | x, y_i,<t) / pi_old(y_i,t | x, y_i,<t)`
- `policy ratio（策略比率）`：新策略与采样旧策略在该 token 上的概率之比
- `clipped surrogate（裁剪代理目标）`：允许策略朝有利方向更新，但不让一次更新走得过远

如果 `A_i > 0`，这条回答里的已采样 token 倾向于整体增大概率；如果 `A_i < 0`，它们倾向于整体减小概率。换句话说，终局奖励给出了方向，却没有告诉模型究竟是哪一步推理立了功或犯了错。

这叫 *outcome supervision（结果监督）*，而不是 *process supervision（过程监督）*。

### 意译层（达）

GRPO 做了一笔强假设：回答赢了，沿途每个动作都“沾光”；回答输了，沿途每个动作都“背锅”。因此，组内基线解决了奖励的相对尺度，却没有解决 token 级信用分配。真正进入梯度之前，还必须选择以“回答”为统计单位，还是以“token”为统计单位。

**结构标注：** 核心机制——指出序列奖励与 token 更新之间不可省略的广播步骤。

### 碰撞问题

你会接受“最终答案正确，所以整条推理链中的每个 token 都应被同比例强化”吗？如果不接受，你认为错误更可能集中在推理链的哪一类位置：分叉点、计算步骤，还是最终格式？

## 3. `[骨]` 两种分母，就是两种训练目标

设一个 batch 中有若干回答，回答 `i` 的长度是 `T_i`，每个 token 的代理项记作 `s_i,t`。

### 目标 A：先按回答平均，再对回答平均

```text
J_sequence = (1 / G) * sum_i [ (1 / T_i) * sum_t s_i,t ]
```

它表达的是：*每条回答拥有同等投票权。*

回答内部再除以 `T_i`，意味着一条 20-token 回答和一条 200-token 回答，对 batch 总目标的权重相同。于是短回答的每个 token 分到的权重更大：前者每个 token 是 `1/20`，后者是 `1/200`。

### 目标 B：把全 batch 的 token 一起平均

```text
J_token = [ sum_i sum_t s_i,t ] / [ sum_i T_i ]
```

它表达的是：*每个 token 拥有同等投票权。*

于是 200-token 回答因为包含更多动作，对总梯度的贡献原则上约是 20-token 回答的十倍。

### 点睛层（雅）

这里的 `normalization（归一化）` 不是为了让数值好看。分母在定义“谁是一个样本”：

```text
除以回答数 -> 回答是样本
除以 token 数 -> token 是样本
```

这与 08-03 DoReMi 的数据配比、08-11 难负例采样、08-12 importance sampling 是同一个形状：你以为自己只是在改变数据如何进入计算，实际上是在改变期望是对哪个分布取的，因此改写了目标函数。

**结构标注：** 核心论点——长度归一化选择隐含了优化对象。

### 碰撞问题

*作者这段最想说服你接受的一个点是什么？你接受吗？*

压力测试：如果有人说“无论怎么平均，样本足够多时都会收敛到同一个好策略”，你会怎样反驳？提示：先问两种写法对长度分布赋予的概率质量是否相同。

## 4. `[肌]` 两条回答的数值例子

同一道题采样两条都得到正优势的回答：

```text
回答 S: 长度 10，A = +1
回答 L: 长度 100，A = +1
```

暂时假设每个 token 的策略比率都相同，代理项也相同。

在 `J_sequence` 下：

```text
回答 S 的总权重 = 1/2
回答 L 的总权重 = 1/2
S 中单 token 权重 = 1/(2*10)  = 0.05
L 中单 token 权重 = 1/(2*100) = 0.005
```

短回答每个 token 的更新强度是长回答的 10 倍。

在 `J_token` 下：

```text
总 token = 110
S 的总权重 = 10/110
L 的总权重 = 100/110
任一 token 权重 = 1/110
```

长回答整体贡献更大，因为它包含更多被策略选择的动作。

这两者没有抽象意义上的“绝对正确”。如果任务的评价单位是完整答案，按回答等权很自然；如果每个 token 都被视作一次动作，按 token 等权更接近动作级经验平均。关键是要知道自己选了什么，而不是把框架默认实现误当成数学定理。

**结构标注：** 数值证据——把抽象的长度权重差异显式化。

以上 1 段在支持骨架段 3 的论证。

## 5. `[骨]` 长度偏置不等于“模型一定变短”

最容易犯的错误是把“短回答每 token 权重更大”直接翻译成“模型一定越来越短”。这一步太快了。

训练中的实际长度变化至少由四股力共同决定：

```text
1. 奖励函数：正确性、格式、长度惩罚分别偏爱什么？
2. 归一化：回答等权还是 token 等权？
3. EOS 动作：结束回答本身也是一个被更新的 token 选择
4. 数据相关性：高奖励回答在当前任务上究竟更长还是更短？
```

如果高奖励答案通常较短，那么按回答归一化可能进一步放大短答案中每个 token（包括 EOS 附近动作）的更新；如果复杂题的高奖励答案通常更长，序列等权未必压倒奖励本身的长度相关性。

还有一个更隐蔽的问题：同一序列优势广播给所有 token 后，大量“无功无过”的常见连接词也会被强化。长序列包含更多这类无关动作，梯度噪声随之进入。这不是单纯的长度偏好，而是 *credit dilution（信用稀释）*：奖励信号被摊到了大量并不决定结果的动作上。

**结构标注：** 让步与边界——区分“目标中的权重偏置”和“最终策略的可观测长度变化”。

### 旁逸：它和检索中的 mean pooling 是同一个形状

这里的序列平均，与 07-22/07-25 讨论的 embedding mean pooling 有深层同构：

```text
Embedding: 很多 token -> 一个句向量 -> 决定性实体可能被平均掉
GRPO:      一个奖励 -> 很多 token -> 决定性动作可能无法被定位
```

一个是“多压一”，一个是“一摊多”；方向相反，病灶相同：过早聚合让少数关键位置失去可辨识度。

## 6. `[肌]` 如何诊断与修正

### 先诊断，不要只看平均 reward

至少分桶记录：

```text
- response length 的分布与漂移
- reward vs length 的相关性
- 每个长度桶的 accuracy / format pass rate
- 每条序列的 gradient norm vs length
- EOS token 附近的 log-probability 变化
```

只看平均奖励，你无法区分模型是真的推理更好了，还是学会了迎合奖励器偏爱的长度。

### 三类修法

1. **改归一化单位**：明确选择 per-sequence 或 per-token；也可采用长度指数 `T_i^alpha` 做连续折中，但 `alpha` 同样是在声明价值判断。
2. **改奖励**：将正确性、格式、冗余、长度拆开报告和加权，不让一个标量掩盖彼此冲突的目标。
3. **改信用分配**：引入过程奖励、步骤验证器，或只在可定位的关键动作上施加更有信息量的优势；代价是过程标签和验证器也会带来新的偏置。

**结构标注：** 实践落地——把目标函数差异转成可观测诊断与干预点。

以上 3 组手段在支持骨架段 5：长度现象来自奖励、采样、归一化和信用分配共同作用，不能归因于单一公式。

### 术语表

| English | 中文 | 本文含义 | 位置 |
|---|---|---|---|
| sequence-level reward | 序列级奖励 | 对完整回答给出的单一分数 | 第 2 节 |
| policy ratio | 策略比率 | 新旧策略对已采样 token 的概率之比 | 第 2 节 |
| clipped surrogate | 裁剪代理目标 | 限制单次策略更新幅度的 PPO/GRPO 目标 | 第 2 节 |
| outcome supervision | 结果监督 | 只根据最终结果训练 | 第 2 节 |
| process supervision | 过程监督 | 对中间步骤提供监督 | 第 2、6 节 |
