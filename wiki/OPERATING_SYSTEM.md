# AI 学习与研究：知识操作系统

> 目标不是“收集资料”，而是把每次输入转化为可复用的判断、工作决策或可验证的实验。
> 
> 权威知识库：本目录（`ai-lab/wiki`）。Obsidian 只承载行动、问题、周复盘；NotebookLM 只承载少量需要跨源问答的专题材料。

## 1. 三层分工

| 层 | 工具/位置 | 只放什么 | 不放什么 |
|---|---|---|---|
| 入口 | `inbox/` | 待分诊条目（2 分钟一条） | 已分诊仍滞留的内容 |
| 证据层 | `raw/` | 原文、PDF、转录、URL、来源元数据 | 未标注出处的结论 |
| 知识层 | `entities/`、`concepts/`、`comparisons/` | 经筛选的事实、机制、对比与引用关系 | 原文复制、临时感想 |
| 伴读层 | `notes/` | hermes 每日伴读笔记全文（一天一篇） | 手工长篇摘抄 |
| 闭环层 | `queries/` | focus / companion-log / picks 三件套 | 其他任何文件 |
| 行动层 | Obsidian「能力训练闭环」及项目文档 | 待读、实验、决策、复盘、工作问题 | 大量资料备份 |
| 支撑 | `templates/`、`index.md`、`log.md`、`SCHEMA.md` | 模板、索引、变更日志、建页规范 | 内容本体 |
| 退役 | `_archive/` | 不再参与流程但暂留历史的文件 | 活跃文件 |

想法层与事实层适用不同规则：`notes/`、`concepts/` 是**想法层**——允许冗余、
矛盾并存、同一主题换角度反复出现，靠使用和引用竞争淘汰；`entities/`、
`comparisons/` 是**事实层**——只求准确与更新，去重合并，不参与"竞争"。
清理和挖掘时不要用同一把尺子量两种东西。

`NotebookLM` 的用途：针对一个明确专题，把已过筛的 5–20 个来源放入一个 notebook 做对话式阅读；它不是第二个总仓库。

## 2. 入口：先判定，再入库

任何链接、论文、视频或想法先进入 `inbox/`。移动/碎片场景不必开电脑：
把链接直接发给 hermes（飞书/微信），它会代写 inbox 条目。一条记录只花 2 分钟填写：

- 来源和 URL
- 为什么值得看（对应哪个当前问题）
- 类型：`paper` / `article` / `video` / `idea`
- 去向：`drop` / `read` / `ingest` / `experiment`

准入规则：不回答一个具体问题、不能影响当前工作或没有复用预期的内容，直接 `drop`。收藏夹不是养老院，别给信息垃圾发编制。

## 3. 处理流水线

```text
捕获 → 每周分诊 → 深读/核验 → 原始证据(raw) → 原子知识页 →
关联现有概念与比较页 → 行动卡/实验 → 周复盘与应用验证
```

### A. 捕获（随时）
- 把条目追加到 `inbox/README.md` 的“待分诊”。
- 同一来源不重复收集；先搜索是否已有原始文件或相关页。

### B. 分诊（每周 30 分钟）
- `drop`：不值得继续。
- `read`：仅阅读，不建知识页。
- `ingest`：需要进入长期知识库。
- `experiment`：能直接回答工作/产品问题，必须写验收标准与截止日。

### C. 入库（仅 ingest）
1. 保存原始内容到 `raw/{articles,papers,transcripts}`，附来源、入库日、校验和。
2. 只创建“可复用结论”页面；满足 `SCHEMA.md` 的建页阈值才新建。
3. 至少链接两个已存在概念，并更新 `index.md` 和 `log.md`。
4. 为知识页增加“对当前工作的含义”：RAG/召回、Agent、模型评估或产品化。
5. 内容有争议、时效或非一手信息时，用 `confidence` / `contested` 标记，不把猜测镀成真理。

### D. 应用（每周至少 1 件）
从本周内容中选一个可检验动作，写入 Obsidian 的训练闭环：
- 假设：我认为 X 会改善 Y。
- 行动：做最小实验或设计评审。
- 指标：离线 recall / NDCG、成本、延迟、人工偏好或明确的决策结果。
- 复盘日期：不晚于两周。

“读完觉得很有道理”不算应用；那只是知识在脑内短暂停车。

## 4. 双周节奏（总投入约 90 分钟/周）

| 时间 | 动作 | 产物 |
|---|---|---|
| 随时，2 分钟 | 捕获到 inbox | 待分诊条目 |
| 周一，20 分钟 | 分诊与清空 inbox | `drop/read/ingest/experiment` 决定 |
| 工作日，40 分钟 | 深读一个高价值输入或跑一个实验 | 结构化笔记 / 实验记录 |
| 周日，30 分钟 | 填 Obsidian 闭环、结算两周前假设 | 判断校准、下一周问题 |

## 5. 季度清理

- `raw/papers` 是证据归档，不应默认全量同步到 Git。大文件保留在本机或 Drive；Git 只保存 Markdown、索引和必要的小型附件。
- 每季度审查一次：过时比较页、孤立页面、没有对应行动的高频主题。
- 运行 `python3 scripts/wiki_healthcheck.py`，修复缺 frontmatter、未入索引、过期页等问题。

## 6. 伴读推荐闭环（hermes × Claude）

三个文件承载闭环，全在 `queries/`，git 双机同步：

| 文件 | 谁写 | 谁读 |
|---|---|---|
| `current-focus.md` | 我 + Claude（挖掘后更新薄弱点） | hermes 兜底选片 |
| `companion-log.md` | hermes（每日推送记录 + 回收反馈） | Claude 挖掘薄弱点 |
| `picks.md` | Claude（本地/工作机写选片队列） | hermes 优先消费 |

- **hermes 每日 9:00**：git pull → 若远端有 `mining/*` 兜底分支
  （云端挖掘推 main 失败时的落点），先 merge 进 main、删除该分支再继续 →
  补漏昨夜 23:30 后的反馈 →
  优先消费 picks 队列，空则按 current-focus 规则自选 → ljg-read 伴读推送 →
  伴读全文存 `notes/`、companion-log 记一行索引 → git push。
  不去重：薄弱点还在就换角度继续推。
- **hermes 每晚 23:30（夜间反馈回收）**：把当天你回给 hermes 的反馈提炼进
  companion-log 并推送——这样次日 4:00 的云端挖掘就能读到当天反馈，
  反馈生效周期从两天缩到一天内。23:30 后才回的反馈由次日 9:00 补漏。
- **Claude 挖掘（每日 4:00 云端 routine「每日选片挖掘」自动运行，
  避开 hermes 9:00 前后的 companion-log 推送竞争窗口；
  管理入口 claude.ai/code/routines；深度挖掘仍可随时人工发起）**：
  读 companion-log + 近期 wiki 活动 →
  更新 current-focus 薄弱点 → 往 picks 补 3-5 条选片 →
  把上周反馈积极（"已懂"/有追问深挖）的伴读笔记提炼进 `concepts/`，
  其余留在 notes/ 沉底——伴读层的出口是知识层，不是无限堆积。
  另外几个动作：
  ① **连接度当替补反馈**：用户没留反馈的周，看近期哪些概念被新页面
  反复 `[[链接]]`——链接在长的方向就是"活"的方向，薄弱点向它修正；
  ② **交叉一条**：从近期高反馈的伴读笔记里挑两篇做概念交叉
  （产出新洞见的切面，不是摘要），作为一条 pick 入队——
  跨切面连接正是"统一框架"类薄弱点要求的思维动作。
  ③ **看适应度榜再决定**：`wiki_healthcheck.py` 会输出 notes/concepts 的
  适应度榜（连接度+新鲜度+companion-log 提及）——高分是提炼进 concepts/
  和交叉繁殖的候选，低分是沉底候选，不再凭印象判断。
  ④ **刷新薄弱点的最后确认日期**：反馈或新增链接支持某薄弱点仍存在时，
  更新 current-focus 里它的「最后确认」；超 3 周无支持（healthcheck 会报警）
  就降权或移除——薄弱点不确认就永生，队列会被僵尸方向占满。
  ⑤ **沉底可复活**：已沉底的伴读笔记若被新页面 `[[链接]]`，
  重新进入交叉/提炼候选池——链接就是复活信号。
  ⑥ **每日反哺一页（硬性）**：每次挖掘至少更新一个既有 wiki 页面——
  从近期伴读笔记出发，把它讲到的概念页补一段新内容或新视角，
  加 `[[对应伴读笔记]]` 反向链接并刷新 `updated:`；笔记提到的
  entities/comparisons 页有事实增量也顺手更新（没有就不强造）。
  同主题伴读笔记攒到 ≥2 篇而概念页还不存在时新建。
  伴读只写 notes/ 而概念层不动，入链信号会饿死、适应度榜就成了摆设——
  反哺是连接度数据的唯一来源。
- **周一提醒**：附带 inbox 待分诊数与 picks 队列余量。队列由每日挖掘自动
  补满 5 条，余量 ≤2 说明云端 routine 可能停摆，去 claude.ai/code/routines 检查。
- **反馈习惯（闭环命脉）**：读完伴读哪怕只回 hermes 一句话
  （"懂了"/"哪步没跟上"）——反馈只从 hermes 会话回收，
  留在脑子里或说给别人的都不算。
- **停摆检测**：连续 2 天没收到 9 点推送就跑 `hermes cron status`；
  `wiki_healthcheck.py` 会在 companion-log 静默 >2 天时报错。
- 运行依赖：本机 hermes 在线。`papers-recommended.log` 已退役进 `_archive/`。

## 7. 成功指标

1. Inbox 待处理条目不超过 10 个。
2. 新增来源中，至少 30% 形成工作决策、实验或可复用方案。
3. 每周至少有一个“从知识到行动”的可验证闭环。
4. 新知识页在创建时即被链接到既有网络，而不是成为 Markdown 孤儿。
