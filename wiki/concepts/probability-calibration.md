# 概率评测——区分 / 校准 / 决策效用与适当评分规则

一个模型的输出可以被当成三种不同的东西来用：**排序分数**、**概率**、**决策依据**。
「模型准不准」不是一道题而是三道——区分（会不会把正例排前面）、校准（报出的
概率是否与实际频率相符）、决策效用（按真实代价选阈值后是否划算）。三者互不蕴含，
必须分别测量。把一个模型压成单一「准确率」或「AUC」，等于用一道题的分数替另外
两道题背书。

## 骨架：一条链，三处独立验证

```text
模型输出分数 s(x)
        |
        +--> 只看相对次序 ------> 区分/排序 ------> AUC, PR-AUC, NDCG
        |
        +--> 解释成概率 p(x) ---> 概率是否可信 ----> NLL, Brier, ECE
        |
        +--> 接入行动规则 ------> 决策是否划算 ----> cost, utility, threshold

排序好  -X->  概率准  -X->  决策好
  ^              ^              ^
分别验证       依赖分布       依赖真实代价
```

`-X->` 表示「不自动推出」。把分数做任意严格单调变换（0.9→0.99、0.6→0.84），
样本次序不变故 **AUC 不变**，但概率含义已被改坏——AUC 只看「谁在谁前面」，
不看「你把话说得多满」。反过来，一个对全体都报基础率的模型可以完美校准却毫无
区分力。[[2026-07-30-calibration-vs-ranking]]

## 适当评分规则：让「说真话」成为唯一最优策略

评测者想让模型报告它真正相信的条件概率 `q`，但只能看到它报了什么 `p` 和一次结果
`y`，无法打开模型读取 `q`。**适当评分规则（proper scoring rule）**是一份激励相容
的概率合同：模型可以夸大或缩小把握，但从长期期望看撒谎不占便宜；**严格适当**
（strictly proper）时，`p=q` 是唯一期望最优解。这不是道德劝告，而是损失函数的代数
结构逼出来的。[[2026-07-31-proper-scoring-rules-honest-probabilities]]

两条主力规则，都把「诚实报告」变成最优，但风险性格不同：

```text
Brier loss  = (p - y)^2
   期望分解  E = (p - q)^2 + q(1-q)
             \_______/   \______/
             报告失真代价  不可消除的固有不确定性
   → 唯一最优 p=q；对极端自信错误有上界，惩罚温和、可分解出 calibration/resolution

log loss (NLL) = -[y·log p + (1-y)·log(1-p)]
   期望分解  E = H(q) + KL(Bernoulli(q) || Bernoulli(p))
             \__/   \________________________/
             固有熵   报告偏离信念的额外代价（excess risk）
   → 唯一最优 p=q；对「把真实结果说成几乎不可能」惩罚无上界，极敏感也易被脏标签放大
```

两处 excess risk 的形状分别是**平方距离**与 **KL 散度**——这不是巧合，而是把训练与
评测接到同一个数学框架的接缝。

## 统一：MLE / NLL / 交叉熵 / KL / properness 是同一对象的五个名字

log loss 的期望分解直接暴露出「统一数学框架」薄弱点要的那条同源关系：

```text
训练视角：最小化样本 NLL   ≡  最大化观测数据似然（MLE）
总体视角：最小化期望交叉熵 ≡  最小化 H(q) + KL(q||p)
激励视角：KL 只在 p=q 时为 0 ≡  如实报告是唯一最优（strictly proper）
```

- MLE 问：参数怎样让观测数据更可能？
- NLL 问：优化器要最小化什么样本损失？
- 交叉熵问：真实分布与预测分布的平均编码代价？
- KL 问：错误报告比诚实报告多付多少分布失配代价？
- properness 问：这套代价是否让说真话成为最优？

它们不是五件工具，而是同一对象在不同问题下的名字。这条链把 [[dpo]] / [[rlhf]] 里
「KL 锚」与评测端「excess risk = KL」接成同一个 KL——但沿闭环数一圈，其实有三处工位
在使唤同一个 `KL(q‖p)`，角色与方向各不同：

```text
KL(q‖p) 的三副面孔（沿数据→训练→评测闭环，从后往前排）
  蒸馏/构造端（InfoNCE·KD）：KL 是「目标」——主动把 student 拉向教师软分布 t（优化项，主动最小化）
  训练/对齐端（DPO/RLHF）：KL 是「锚」——把策略拴在 π_ref 上，越小越保守（约束项，被动约束）
  评测端（proper score）：KL 是「尺」——log loss 相对诚实报告多付的超额风险（度量项，被动度量）
```

差别全在**谁在动、谁不动、方向性**：蒸馏里 `p` 主动追 `t`、DPO 里 `p` 被 `π_ref` 拴住、
评测里 `p` 与 `q` 都固定只做一次度量。本页 log loss 的 excess risk = KL 只是这三副面孔里的
「尺」；[[2026-07-13-infonce-vs-kl]] 把 InfoNCE 写成「目标为 one-hot 的 KL」、蒸馏写成
「目标为软分布 t 的 KL」，补上「目标」那一副，与 [[dpo]] 内生化的「锚」凑齐同一散度贯穿
闭环三环——「统一数学框架」薄弱点要的正是这种跨环节动作：不是记住三个 KL，而是认出它们
是一个 `KL(q‖p)` 在不同工位换岗。

## ECE 与「聚合抹掉少数信号」同构

ECE（期望校准误差）先把预测概率分箱，比较每箱平均置信度与实际正确率，再按样本数
加权。它直观但**不是 NLL/Brier 的替代**：箱太少掩盖局部失真、箱太多受小样本噪声
影响；更危险的是**单一 ECE 会掩盖关键子群**——整体校准不代表某语言、某肿瘤亚型、
长尾实体上也校准。

```text
编码端：token -> 过早平均 -> 关键实体消失
评测端：group -> 过早平均 -> 关键失准消失
```

这与 [[benchmark-evaluation]] 里「总分掩盖切片」、[[text-embedding]] 里「mean-pooling
淹没专名」是**同一种过早聚合病**，修法也同构：拒绝在报告前平均，展开 per-slice /
reliability diagram / worst-group 再看。

## 校准好 ≠ 决策好：最后一环要接真实代价

校准是「预测与结果」之间的性质；效用还要把**行动**纳入。模型准确报出患病概率 10%，
要不要治疗仍取决于漏诊代价、副作用成本、是否有便宜复检——**最优阈值来自代价，
不是从 0.5 天然掉下来**（0.5 只在对称代价下才对）。且校准必须带三个限定词：
*在哪个时间、哪个人群、哪种分布上*——验证集上校准，上线后基础率一变，排序没坏、
概率刻度却整体偏移。

## 边界：proper 不保证目标分布是对的

严格适当只解决一个局部问题——给定目标分布，什么报告最优。它**不**自动解决：有限
样本（小切片上更好的概率模型可能暂时得更差分，要报置信区间/bootstrap）、分布漂移、
选择性预测（拒答/挑易题会刷高分，必须 risk-coverage 一起看）、以及**代理目标**：

```text
proper scoring rule
      +--> 报告对「被评分的标签分布」诚实
      -X-> 标签无噪声（医疗诊断、标注者偏好、judge 自身偏差都在污染 q）
      -X-> 数据与线上同分布
      -X-> 下游决策效用最大
```

于是「一个指标可以在数学上完全正确，却在系统层面回答错问题」——这正是端到端闭环
的关键边界：**目标一旦错了，优化越成功，模型越稳定地学错**。proper 保证 `p` 追向
观测标签的条件分布，不保证那个分布就是业务真相。这也把概率评测接回 [[benchmark-evaluation]]
的 reward overoptimization：judge/标签只是目标的代理时，诚实地钻代理的空子仍会发生。

## 修法预告：temperature scaling 只改刻度、不改排序

若后处理只调一个温度参数 `T`（logits/T 再 softmax），argmax 与全部排序不变，却能显著
修好 NLL/ECE。这恰好把三个问题彻底分开——它改的是模型**表达把握的刻度**，不是模型
的**知识**，也不动**区分力**。「校准变好」因此可能只意味着「学会更合适地下注」，
而非「知道得更多」。

## 一套不会被单指标骗过的评测顺序

```text
1. 先定义行动：输出用于排序、阈值触发、拒答，还是概率沟通？
2. 测区分：AUC / PR-AUC / Recall@K / NDCG
3. 测概率质量：NLL + Brier（是否自信地犯错）
4. 展开校准诊断：reliability diagram + ECE（失真在哪个置信区间）
5. 做关键切片：时间/人群/语言/领域/长尾实体/难度（平均掩盖了谁）
6. 接入真实代价：cost curve / expected utility / abstention curve
7. 上线后重验：监控基础率、输入漂移、校准漂移
```

前四步评模型，后三步评系统。缺任何一项，「数学上 proper」都可能变成「系统上答非所问」。
